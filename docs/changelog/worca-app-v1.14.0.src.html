Setup

A setup assistant, proxy included.

Behind a corporate proxy, nothing worked until someone set environment variables?
Now the Setup assistant checks this machine, sets up the network, signs in to model providers and picks models, then applies everything in one step. On a corporate proxy, log in once with your Windows account: Worca keeps a hash, never the password. Chat can test the proxy and suggest a fix for you to apply.

Engines

Four more engines, for runs and chat.

Want Worca on a model your company already pays for?
Now Gemini CLI, Qwen Code, OpenCode and Goose run a workflow's steps, and Chat works on each of them, next to Claude, Codex and Copilot. Pick one per run on New run, or set a default in Settings › Models. In Chat, an engine's own tools stay off and every feature goes through Worca, so a chat behaves the same whichever engine answers.

Ship

One Create PR for runs and features.

A feature split into five runs meant five pull requests by hand?
Now Create PR works the same for one run, a feature, a chain or a group you made. Choose separate pull requests or one combined pull request; Worca builds the combined branch without touching your checkout. The dialog opens with a description already drafted, and Watch PR follows the checks and reviews.

Team

Share agent memory with your team.

Your agents learned a project's traps, but a teammate's start from zero?

Chats

Chats, organised like your runs.

Lost track of which chat had the answer?
Now the Chats column works like the Runs list: Pinned, Today and Recent, archive, and search from the top bar. Put related chats in a group with a suggested name, and ⌘-click or Shift-click to select several. Commands in a chat show a one-line summary of what they do, and a reply no longer moves your place or your cursor.

Plugins

Start a run from a Jira ticket.

Copying a ticket into Worca, then pasting the PR link back?
Now the Jira plugin lists a project's issues, with a JQL filter and search, and a run starts with the ticket's description and comments as its task. It is titled with the ticket's key and title right away. Turn on Write result back and a finished run comments on the ticket with its summary and PR link, and can move it to the next status.

Requirements

Define a feature before it is built.

A run went wrong because the task left half the questions open?
Now describe a feature in a few sentences and Worca interviews you, a few questions at a time, then writes a spec you can test: goal, flow, edge cases, rules and acceptance criteria. Six checks say when it is Ready, and Start in Worca begins an ordinary run with the spec as its task. Nothing runs before that.
