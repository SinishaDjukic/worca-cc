Recovery

Runs pause. Only you stop them.

A model-side 500, a rate limit, an expired login — none of them end a run any more. The run pauses with its worktree intact, Resume retries the failed node in place, and the task source hears needs-human, not failed.

Ask Worca

Drop in a screenshot. It sees it.

Images and PDFs attached to an Ask Worca message reach the model — stored raw on disk, read natively, never inlined into the prompt. And a chat can be pinned to a project or workspace, whatever page is behind it.

Guardrails

Agents can't kill the host.

On Aug 31 an implementer cleaning up test servers matched the production argv and killed the server orchestrating it. Every spawn now carries a hook that denies process-wide kills, the host PID in its env, and a preamble that names both.

pkill · killall · xargs kill deniedliteral PIDs still allowedmacOS · Linux · Windowsspawn diagnostics toggle
What the PreToolUse hook says
ps aux | grep '[n]ode --disable' | … | xargs killBLOCKED · pipe-fed
pkill -f server.mjsBLOCKED · process-wide
taskkill /IM node.exeBLOCKED · by name
kill 48213allowed · literal, not the host
The host PID travels in every spawn envWORCA_HOST_PID · survives scrub ✓

CLI

One command owns the UI.

worca ui start · stop · restart · status replace the twenty-line stack trace you got when the UI was already up. Already running is exit 0 and the URL; another program on the port is two lines and exit 1. And worca --version finally answers.

--port · --open · --mockexit 0 = runningtoken-guarded shutdownworca -vclean exit on Windows
Already running is not an error
$ worca ui start
Worca UI is already running at http://localhost:4317
  Open it:      http://localhost:4317
  Restart it:    worca ui restart
  Another port:  worca ui --port 4318
$ worca ui status → exit 0
$ worca ui stop
Worca UI stopped · POST /api/shutdown, bearer token from ui.json

One UI per machine, by design: two instances would each spawn chat workers and fight over runs.
