Shipping

Publish a branch without a pull request.

Want a teammate or CI to try a run's work before anyone reviews it?
Now press Publish branch: Worca pushes the branch and opens no pull request. Fix what testing finds, press Push changes, and open the pull request when it is ready, as a draft if you like.

no pull request openedfixes push to the same branchopen PRs as draftsmerging closes the issue
From finished run to merged
  1. 1Publish branch: the branch is on origin, no pull request yet
  2. 2A teammate or CI checks it out and tests it
  3. 3You fix what they found and press Push changes
  4. 4Create PR, ticked Open as draft
  5. 5The merge closes the issue the run came from

Workspace runs publish one branch per project, each with its own tick.

Ship it: the pull request can now open as a draft.

Guardrails

Agents can't touch Worca's own files.

Worried a prompt-injected agent could rewrite the tool that runs it?
Now the Normal and Strict guardrails keep agents out of Worca's database, settings and secrets, and away from its plugins and scripts. Strict also blocks the network commands it missed before.
