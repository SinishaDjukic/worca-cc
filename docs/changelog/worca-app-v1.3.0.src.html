Auto workflow

The workflow picks itself.

Ever wondered which workflow to pick for a task?
Now Worca can pick one for you. Start a run on Auto: Worca reads your task, takes a quick look at the repo, and proposes a workflow that fits. Review the proposal first, or let the run go ahead on its own.

Memory

Agents that remember the repo.

Tired of agents relearning your repo on every run?
Now Worca keeps a memory: short Markdown notes, per project and global, that every agent reads before it starts and can add to when it learns something. You read and edit the notes on the new project page, and a built-in workflow tidies them up.

per project and globalagents read it and add to itedit it yourselfone-click tidy-up

Memory never ends up in your branch: the run keeps it out of git and out of every commit it makes.

The project page, Memory tab — health at a glance, every file with the run that wrote it, and the editor.

Team

Team metrics & spend dashboard.

Want to know what your whole team spends on runs, not just your own machine?
Now every finished run is recorded to a small worca-metrics branch in the project's own git remote, and a new Team metrics page adds it all up: spend, runs, duration, autonomy and review cycles, per project or per workspace. No extra server, and Ask Worca can answer questions about it.

Runs

Every step leaves a paper trail.

Ever wanted to see exactly what the planner or the reviewer wrote in a given cycle?
Now every file a run produces is filed under the step that produced it. An Artifacts tab on the run lists the plans, reviews, patch and results with a viewer for each, and Ask Worca can read the same files while a run is still going.

Review

Talk about the diff, on the diff.

Left a comment on a diff and lost the answer somewhere in the chat?
Now a comment is a thread. Reply to it right in the Diff tab, or ask Worca and its answer lands under your comment, next to the code. Comments render markdown, with a preview before you post.

replies next to the codeWorca answers in the threadmarkdown, with preview

The Diff tab — your question under line 19, Worca's reply beneath it with a code block, both markdown.

Your question and Worca's answer, on the same line of code

Sorting by Number(id) assumes ids are numeric strings. Should the merge keep the oldest row by createdAt instead?
ResolveAsk WorcaReply

Nothing enforces numeric ids. createdAt is the safer key — switching the sort in the fix pass, with a test.

Resolving a thread resolves the whole conversation. Worca may delete its own reply, never yours.
