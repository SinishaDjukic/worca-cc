How the composite works (Task 21)
1A fresh token on the expands input (task, json) with no fresh fix trigger starts ONE composite execution — never N cards; everything collapses under this node.
2Phases run sequentially; each phase's task sub-executions run in parallel under the semaphore (WORCA_MAX_PARALLEL, default 4). Each clones the node with task bound to that task's FILE + the slice directive rendered.
3Rows are recorded as {executionId: x:n_impl:1:p<P>t<T>, kind:'task', phase, taskId} — labels are truncated task titles. Sibling failure aborts the composite.
4The node's outputs fire ONCE at the end (done); worktree staged after the last phase. Then the reviewer runs on the whole diff.
5A blocking review re-fires fix — a single normal execution on the combined diff (kind:'cycle', labeled “cycle 2 · fix”), NOT a re-fan.
6Row click filters the run log to that executionId. Header shows summed cost/duration. Pinned geometry: strip 26px, rows 22px (nodeSize footerRows); phase separators here are demo sugar.
