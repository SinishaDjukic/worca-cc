# Forms and suggestions

| Rule | What | Why | Held by |
|---|---|---|---|
| `form.dialog` | A step that needs fields is one Dialog: framing sentence, Fields, a foot that names what happens | You know what the button does | by hand |
| `form.check-at-save` | A Dialog's Fields are checked once, when you press its Save or Next: what is wrong stays in the status line, the Dialog stays open, typing clears the line once it is mended; a hint that promises a format is checked; a Save that changed nothing closes without a toast | One moment, and no Save that turns off while you are still typing | by hand |
| `form.name-limit` | A name you type (a title, a schedule's name) stops at 80 characters | A name has to fit on a row and in a card | by hand |
| `form.suggest` | Worca's text runs on a helper job; if it cannot write, the field keeps its text and says so | A suggestion never blocks you | by hand |
| `form.rewrite` | A rewrite is a suggestion of the whole text: shown beside the field, taken with Use this, undone with Undo; gaps are amber marks naming a perspective; the field keeps its text until Use this | The person's words are never lost, and what is still open stays visible | by hand |
| `form.composer` | The composer sits in one place on every page that has one (Chat, a conversation, a schedule's page): on the cards' rail and as wide as the cards; on a home at one height under its heading, so moving between places never shifts it. Starting anything is one composer: you pick Ask, Task or Schedule; the sentence and Customise open under the words; its button names what will happen. Its engine carries its effort; a meter says how full the chat's context is; while Worca replies, what you write can be queued (remove; `form.composer-queue`) and goes when the reply ends; @ names a task, which becomes a chip leading to its card; voice has a hands-free mode. A task is started one way: Task in the composer, a starter or an ask each show the proposal, and its Start dispatches. While Worca replies, sending queues, as does its quiet **Queue** button beside Stop; Stop keeps its place, the last button. An armed starter's chip takes the mode word's place. On Chat home a row of starters (pinned workflows first, Shaper by default, then New task, Build workflow, Schedule a run, Track a run, More with the rest, presets and Pin a workflow) only arms the composer: a chip with its name and ✕, and its placeholder; nothing is sent until you send, and each starter sends into its own flow of cards. A message is never read as a task | One way in, and ordinary stays ordinary | worca-sweep |
| `form.composer-queue` | While Worca replies, a message you send waits above the composer, as up to three rows (oldest first), each with Remove; to change one, Remove it and write it again. A quiet **Queue** beside Stop queues what you wrote exactly as Enter does (same cap, same words); Stop keeps its place and look. The rows and their line sit on the composer's rail: the same left edge and width, never wider. One line says when they go (`Sends when the reply finishes`, `Queue full: …`). A finished reply sends the oldest, one per reply; once it is on its way, Remove says it was already sent. A stopped or failed reply, or one that ended while the chat was closed, pauses the queue: the line says why, and **Send now** sends it. A refused send never drops the text | A message you wrote is never lost, and nothing is sent you did not see coming | stillhet-chat-queue-host |
| `form.export-folder` | Exporting a workflow as a Worca plugin asks where in the export form itself: one Field, Folder, under the sentence `As [a Worca plugin ▾] with the agents it uses`, with its hint (the plugin is written into this folder); a refusal names the action and dev's reason (`Could not export Full: pluginDir is required for a plugin export`) and writes nothing | The one thing the plugin needs is asked where you choose it | stillhet-workflow-live |
| `form.import-confirm` | A workflow file that runs scripts on your machine asks before it is imported: a ConfirmStrip, `It runs N scripts on your machine. Import it?`, Import or Cancel; Cancel imports nothing | A file never runs code on your machine without your word | stillhet-workflows-host-roundtrip |
| `form.schedule-page` | A schedule's page says how it runs in one sentence of SentencePickers: Repeats and at (a rule with no word, every 2 days, shows dev's sentence as the checked item); in Expert a second line: what it does while one still runs, after how many failures it pauses, what a missed time does and, when it runs late, how late at most (dev's grace window). Each pick changes the draft (`rail.drafts`), never the schedule, until Save. A one-off is `Once at`; one that waits for a run says `after TITLE` in place of a time, and TITLE is a SentencePicker of what it can wait for (its project's other one-offs and running tasks). A one-off still to come offers **Run after this**: the New task form, starting once it ends. Delete's notice names the one-offs that wait for it (they will be marked missed). A schedule that runs a saved preset says `from PRESET`, or `preset deleted`. Skip next time becomes **Keep next time** while a time is skipped. A series that reached its end sits in its own section, **Ended**, with no next time and no Run now | Every fact dev keeps about a schedule has one home, in words | stillhet-schedules-drafts-host |
| `form.plugin-setup` | Set it up happens on the plugin's own page: a plugin that asks for nothing and is not Needs set-up says so; otherwise a ConfirmForm opens under its head, one Field per value it asks for (a secret is a password Field; one already set reads `Set; type to replace`), and its sentence names the plugin. One part per target the values are saved with (a task source, a chat channel, the model keys), each with its own Save, so a refusal changes nothing and names dev's reason; a source's first profile is made in the same Save and taken back if the save is refused. It asks for the required values: the everyday ones, and an advanced one only while it is empty; other advanced values and extra profiles stay in Settings › Plugins. It never says `is set up` while the plugin reads Needs set-up | A plugin is ready where you found it, without a trip to Settings | stillhet-marketplace-host-actions |
| `form.update-asks` | An update that asks for something new asks first: a ConfirmStrip under the head, `Update jira-source to 0.2.0? It now asks for …`, Update or Cancel; Cancel applies nothing. An update that asks for nothing new goes on one press | Nothing new reaches a plugin without your word | stillhet-market-live |
| `form.rename-project` | A project is renamed from its ⋯ menu (on its page and on its bar row): `Rename…` opens a ConfirmForm under its head, `What should NAME be called?`, one Field `Its name` (at most 80 characters, `form.name-limit`), and Rename or Cancel. A name another project has is the Field's error; the same name closes the form. Its key and its folder never change | A name is yours to fix without removing and adding the project again | stillhet-projects-host-actions |
| `form.remove-owned` | Removing a project whose folder Worca made says so before Yes: `Remove NAME? Worca made its folder, so the folder goes too; its tasks stay, and its schedules stop.` Any other project keeps its folder and the strip says that | A folder is never deleted unasked | stillhet-projects-host-actions |
| `form.link-remote` | Link a repository… (and Link a remote…) on a project only on this computer asks its address first: a ConfirmForm `Where is the repository of NAME?`, one Field `Its repository address` (an `https://`, `ssh://` or `git@` address), Link or Cancel; nothing is pushed | Worca cannot guess a repository address, and a link with no address would fake it | stillhet-projects-host-actions |
| `form.add-project` | Add a project by hand is one ConfirmForm with a Segmented `One folder · New folder · Several folders…`. One folder has Choose folder… (the FolderBrowser) and the probe line under its Field, with Use git for a plain folder; New folder has `Its name`, Use git and where it will be made; Several folders… has the FolderBrowser in a Dialog, then the review list, where skipped rows keep their reasons until they are renamed and retried. A refusal is the Field's error or `Could not …` in plain words | Every way classic adds a project, in one place | stillhet-projects-add-ways |
| `form.workspace-edit` | Edit by hand opens with the workspace's Name row (a Field), then its projects (Take out, Add one); every change is one draft with the DraftBar until Save or Discard. Save stops at the first part dev refuses and names what was saved; the draft keeps the rest | A workspace's name and its projects change in one place, and a half-saved edit says exactly what stuck | stillhet-workspaces-host-actions |
| `form.run-options` | New task's run options live in its one Dialog: a saved preset is the frame's leading clause (`from PRESET ▾`, shown only when one exists for the project; its menu offers Update preset while modified, Duplicate and No preset); a ticket source is a segment beside Write it and From file (with a source picked the Segmented takes its own row, its note and inputs under it, never laid over them: F-G-G3-01), its profile gate a ChoiceNote, its connection checked first (not connected: a ChoiceNote with Open the Marketplace page and Test connection), its own inputs before the search (a Field, or a SentencePicker such as Repository), its tickets a search Field over listRows with a check and the picked one's preview; the project's saved engine and tags fill an untouched form, and Cost tags offers Save as default; Agents offers Save as and Reset to the workflow's defaults. Under the text, one ChoiceNote at a time: a broken preset (blocks Start, each item with Reset to default), the engine refusal (with the Allow unguarded Checkbox), the sync refusal (Start from the remote, or Start anyway, and Cancel), else the team policy notes (grey, or amber with a warning; never blocks). A refusal's words are only in its note, never also the form's error line. Chat's TaskProposal shows the same start-time notes (sync, engine, policy) and the saved defaults, and no presets or ticket source | Every choice classic's New run offers has one home, and a refused start tells you why and how out where you pressed Start | stillhet-new-task-options-host |

**A form** (New run, Create PR): a Dialog. It opens with the one sentence that frames the step, its choices as
SentencePickers (`A [large ▾] task`, `branch into dev ▾`), then its Fields. Text Worca can write is a SuggestionField.
A problem with the choice shows before it is made, on the rail with an amber dot: one note, what it means, and
the ways out as buttons. The start button names what will happen (`Start at 16:40`); Cancel is quiet, before it.
A setup of several steps is one Dialog with the Stepper at its head, one step per screen, Back and Next in its foot.
A view that only shows (a workflow graph at full size) is a Dialog without a form: its head, the view, Close.

## Suggestions
- The violet shimmer means Worca is writing text you will review. It never means loading or a run state.
- Every suggestion runs on a helper job's model (Models › Helper jobs) and its sparkle's tooltip names it: PR titles
  and descriptions (stacked ones too) on PR description; run title and branch on Run naming; drafted answers and
  change requests on Drafts.
- If Worca cannot write it (an error, or no answer in 20s), nothing changes: the field keeps the text it had, says so
  in grey (`Couldn't write it … The text is as it was.`) with Try again, and the form still submits.
