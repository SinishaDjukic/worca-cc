Dev's Chats column (#948 s2/s3, #953 retired the `chatsColumn` flag and the old History column) broke a side-chat branch in five silent ways while merging cleanly in app.js/style.css (PR 954 merge, 2026-10-25). See also [[ask-ui-hidden-pins]].

- `mountChatsColumn({host})` does `host.replaceChildren(head, chip, list, bar)`: anything added to `aside.chat-history` in `buildHistory` vanishes. Append extras AFTER the mount (in `mountChats`).
- The column owns the thread list (no `renderHistory`, no `?q=` search — search lives in the top bar's Chats group). A consumer of the rows reads them through `mountChatsColumn`'s `onThreads(threads, view)` (called on every paint); only `view.show === 'all'` is the whole list, and pinned chats lead it (sort yourself for "newest"). TRAP (cycle-1 major): the view is restored from localStorage (`worca-cc.chats.view`), so a consumer that listens only while `show === 'all'` NEVER fires for someone who left the list on Needs you/Archived (the dock's Recent chats + History button vanished; jsdom proof: `bootChat({ local: { 'worca-cc.chats.view': '{"show":"needs"}' } })`). Feed "newest N" from its own `/api/ask/threads?show=all&sort=activity&limit=N` and use `onThreads` only as the All-view fast path.
- `test/ui-chat-style.test.mjs` bans the OLD class names anywhere in style.css (`ask-thread-(row|pick|dot|col|title|meter|when|fill|topics|match)`, `chat-history-(head|…|body|…)`, `chat-new-btn`): reused markup needs new names.
- `.chat-page[data-chats="on"] .chat-history` (and its 1099px media twin) is (0,3,0) and `data-chats="on"` is always set: any `.chat-page[data-x] .chat-history` override ties and must come AFTER dev's block. Dev also hides the composer meter (`[data-chats="on"] [data-ask-meter]`) for the head's `.chat-head-meter`, and adds `.chat-new-plus` + `.runs-resize` (absolute, in the aside) — a re-host must hide or restate each.
- `onChatKeys` is a DOCUMENT listener gated only on `st.open` (⌘\, ⇧⌘L, ⌥⌘N, ⌥↑/↓, `?`); the column's menus, group picker and keys sheet append to `body` (outside `el.page`). A host showing the panel beside another page must gate keys to `el.page.contains(target)` and exempt `.wfv-menu, .group-picker, .keys-modal` from outside-press closes.
- `onChatKeys` is BUBBLE and registered at `createAskPanel` (late in app.js), so every app.js document keydown listener registered earlier runs first and its `preventDefault` silences the panel (`e.defaultPrevented`). Dev's Runs `?` listener (app.js, after the Runs Escape arm; active on every route the Runs section renders) opens the RUNS keys sheet when `?` is pressed on a non-field control inside `#ask-side`: the Chat sheet is unreachable from the column there, while on `#schedules` it works. Every page-level document key listener needs the same `if (e.target?.closest?.('#ask-side')) return;` the Escape arms got. jsdom proof: `bootChat`, `go('runs')`, click `#topnav-ask`, focus `#ask-side [data-ask-side-thread]`, dispatch a bubbling cancelable `KeyboardEvent('keydown', {key:'?', shiftKey:true})`, read `.keys-modal .keys-h` (Runs: "Runs list"; Chat: "Chat page").
- Same root cause for Escape: the `#ask-side` exemptions in app.js's capture-phase Escape arms miss the column's body-level `.wfv-menu`/`.group-picker`. History/Running arms stand down (`runsListOwnsEscape()` checks those selectors), the Runs selection arm too; the PROJECT page arm (`leaveProjDetail`) and the `#workspace-create` arm (`wizClose.click()`) do not. Escape in a chat row's ⋯ menu opened from the side column on `#projects/<key>` closes the menu AND goes to `#projects` (bootChat probe: `go('projects/<key>')`, open the column, click the title, click `.runs-more`, dispatch Escape on the menu item, read `location.hash`).
- Dev paths that remove chats bypass `deleteThread`: `onChatsGone` (Delete group) and `chatsCol.onFrame` (history clear). Per-chat state kept elsewhere (unread dot, recent rows) needs its own cleanup there.
- Old-column tests: the trash is now ⋯ › Delete… (`deleteFromList(ctx, id)` in `test/helpers/ask-panel-harness.mjs`); views via `#chats-view-btn` → `.wfv-menu [role="menuitemradio"]`.
