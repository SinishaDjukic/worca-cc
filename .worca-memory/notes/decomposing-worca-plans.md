Plans assume ONE committing implementer; pipeline implementers must not commit and parallel siblings share one tree ([[pipeline-worktree-node-modules]]).

## Commit-independent steps
An Expected assuming the commit (`git status --short` lists only the new test; `git grep` finds an UNTRACKED file) trips the stop rule. Mutation check = a node script (anchor once, write mutant, `node --test`, restore in `finally`, assert original); "nothing imports X yet" = `grep -rn --include='*.mjs' … | grep -v <own dirs>`; Commit steps are skipped, the `git add` list is the file checklist.
- `git apply --index` is a hidden `git add` (races `.git/index.lock`): drop `--index` (plain apply still refuses drift); note it in the final note, not DEVIATIONS. `git mv`/`git rm` only alone in a phase.
- Earlier phases' new files read ` A`, not `??` (`_stageWorkingTree` = `git add -A -N` after each execution): compare paths, never unstage. A later task DELETING them leaves ` D`: finish with `git rm -r -q --cached -- <dir>`, alone in its phase. "`git status --short <dir>` stays empty" is false-red after the first phase touching the dir: snapshot `git hash-object` at task start. Counts need `-uall`.
- `DEVIATIONS.md` lives in the pipeline dir: name it by ABSOLUTE path ("repo root" lands it in the run's commit). Siblings append with ONE `cat "$d/entry.md" >> <abs path>` (an Edit "append" rewrites the file and can drop a sibling's entry).

## Phases and parallel safety
- Task 0 `git switch -c`/`--detach` fails in a run worktree: stay on the branch, link `node_modules` from ONE task, run base checks in a throwaway `git clone -q .`.
- The plans' `t() { rm -rf .worca-cc-test; … }` deletes siblings' homes: task files use `WORCA_HOME="$(mktemp -d)"`, no `rm`; only a task alone in its phase uses `t` verbatim.
- A sibling's red phase can redden your green step: run lists name only tests no same-phase sibling edits (shared ones run in the next solo task); lock around `git apply` on a shared source; keep each command's flags. Exposure = each run-list test's TRANSITIVE import closure on the PHASE-END tree (`ask-api-mcp.test` loads `turn.mjs` via `ui/server.mjs`) + style.css readers, app.js booters, dir scanners (`ui-addons-pages`, `v1-remnants-removed` walk all `ui/public`). A run list naming a sibling's NEW test fails to load while it is red-only: run it in the next phase's preflight.
- Start from the plan's "Waves"; split waves sharing source files (file sets from the fences' `diff --git` headers, never prose). Order = longest IMPORT path from the FENCES, never "Import graph" prose; non-import coupling (string detector ids) sits in the registry task; a Step-4 list running a test another task creates is a constraint. Minimum phases = longest same-file chain; re-derive run-list counts in ACTUAL phase order. A doc most tasks edit: all its edits in ONE phase-1 task. Docs-only and pure-jsdom UI tasks can jump early (no test reads `docs/*.md`; `ui-*` tests import only `ui/public` + `skills-registry/texts.mjs`). Merge two tasks when one's guard turns green only after the other.
- Write importers (app.js, `ui/server.mjs`) last inside a step. Ids `4a`/`4b` break `Object.keys` order: use the heading list. Map scratch commits by subject, never `git rev-parse ':/^T01$'`.
- **Prove a split:** each task's RED and GREEN lists with the sibling absent, red-only and complete, and the plan-order predecessor absent: failing-name sets and messages match plan order, forward and REVERSED sibling order. Strip the clone prefix from file-level failure names (absolute paths) before comparing lanes. A task may jump phases when a phase-order replay ends byte-equal; run the plan-order inversions. One `npm ci` clone feeds every lane's link.
- Mutation lists are measured on the FINAL tree: run each mutant at its task's phase, tag survivors "killed in Task N"; a test moved later needs a mutation proof. A `tested-tree` hash row belongs to the LAST task touching the file.

## Handing fences to tasks
- Absolute line ranges into the PLAN, never a fence ordinal; line numbers in a TARGET file go stale: cite `grep -n '<verbatim rule text>'`.
- Copy each `### Task N` section byte-exact with node (assert `plan.includes(section)`), fence-aware; replay FROM the task files in a fresh clone; scan them for U+FEFF, backslash-u and code points absent from the plan.
- Never hand the implementer Edit-tool anchors: a hash-checked applier (two tasks on one file chain hashes; generate from a CLEAN base), anchor marker regexes, throw on AMBIGUOUS; a "delete these N rules" CSS fence is a SET (remove each line alone).
- Op grammar differs per plan (op lines keyed on line START; ``` or `~~~~+` openers; `**Replace all in \`f\`** … exactly **N**`; `**Delete in \`f\`**` = remove `${old}\n` once; `Find:`/`Replace with:` pairs in order from `git show HEAD:<file>`; path-comment fences): lift the refiner's parser (`/private/tmp/*/apply.mjs`, `replay.cjs`; its `PH` table + `fences.json` must match the CURRENT -vN).
- Prose "replace function X with this fence" leaves X's JSDoc behind, and a later "add `foo,`" can land inside an earlier fence: task files say where both go.

## Self-applying task files
- A node generator copies each section between `<!-- plan:begin Task N -->`/`<!-- plan:end … -->` and embeds the applier as a ` ````js apply-fences ` fence, extracted per step by `awk 'p && $0 == "````" {exit} p {print} $0 == "````js apply-fences" {p=1}'` into a mkdtemp file. Or embed each patch as a `~~~~diff <label>` fence + sha256 with `apply --check` / `apply -R --check` ("already applied"), the plan's extractor `PLAN=` the TASK FILE; never embed the plan's runnable "How to apply" example; end apply lines `else echo FAILED; false; fi`.
- Per file `<!-- expect <step> <path> <before|absent> <after> -->`: at after ⇒ `already applied` (check BEFORE Replace ops); at before ⇒ tmp + `renameSync` only if the result hashes to after; else DRIFT, exit 2. Keep the mode: `chmodSync(tmp, statSync(p).mode & 0o7777)` (a fake claude stub lost its exec bit). A file edited in TWO steps accepts any of the task's before-hashes. A resume re-runs EVERY phase: add `later` hashes (any = superseded, skip); after a review FIX accept `already applied (content present)`.
- An applier shipped as a FILE needs a realpath main guard or none (`import.meta.url === pathToFileURL(argv[1]).href` is false under `/tmp`: exits 0, writes nothing); print `step <k>: done`. Refiner clones use branch `replay`: pick another.
- **Oracles:** the refiner's one-commit-per-task replay (`T<n>` or `T<n>-test`/`T<n>-src`; `git diff c^ c` == fence; step patches by path split `-- test` / `-- ':!test'`); grep the live log for scratch under BOTH `/var/folders/` and `/private/tmp/`. Diff-fence refiners keep one commit per FENCE (`fNN-T<n>S<k>`) + `step-T*S*.log` (plan-order RED baselines). With only a composed tree, rebuild states from the checkpoint + included tasks' `git diff -U0` hunks (check the all-tasks rebuild equals HEAD). `expect` hashes = the oracle's `c^` blobs (try ±1-blank-line variants).
- **Proof:** each phase-end tree equals the plan-latest task's commit; run every `<!-- run N -->` block via `spawnSync('zsh', ['-c', block])` in two fresh clones (siblings forward/reversed), `cmp` trees, every step's `all --check`, re-run for idempotence; stop scanning bash blocks at `## Rules` (the Commit block).
- **Diff-fence plans** ("each diff's base is the end of the previous task") still split: disjoint files commute. One commit per fence in PHASE order (`git apply --recount --check`) must end at the refiner's tree hash (`git cherry-pick` has no `-q`). The integration task hashes the worktree via a throwaway `GIT_INDEX_FILE` (`read-tree HEAD`, `add -A`, `write-tree`) against it.
