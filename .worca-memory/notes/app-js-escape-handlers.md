## Escape and keys
- `preventDefault` does not stop app.js page-level Escape handlers (only the phone drawer checks `defaultPrevented`): History/Running/Projects detail (capture: Details → glance → list), `#workspace-create` (→ `#new`), the guardrail wizard — a popup's Escape closes AND the page steps back. Fix: `stopImmediatePropagation()` in an EARLY document capture listener (side-flyout's `createFlyout` registers first), or a `window` capture listener + `stopPropagation()` (beats every document handler), or `if (e.defaultPrevented) return;` in each handler.
- `graph/composer.mjs` `onKeyDown` (document, bubble) ignores `defaultPrevented`, skips only text fields and `[aria-modal]`, and acts on arrows (8 px moves), Delete/Backspace and Space whatever modifiers, plus Ctrl/Cmd+Z: a menu stops arrows, Home/End, PageUp/Down, Delete, Backspace, Space and Enter with any modifier, letting other Ctrl/Meta/Alt chords pass. Repro: the composer shell from `test/ui-composer-editor.test.mjs` + `createFlyout` on one doc.
- A popup that eats Escape closes on focus leaving (`focusin` outside it, its trigger, `inside()` and submenus — never `focusout`, which re-renders fire), else the field's Escape (Runs search, vim in the terminal) closes it.
- jsdom repro on real app.js: boot `hash:'workspace-create'`, open with a keyboard click (`detail:0`), dispatch a cancelable Escape on `activeElement`, `await tick()`, assert `location.hash`; detail screens `bootDetail` + `openDetail(ctx, 'details/overview')`. Dispatch `hashchange` only when the hash changed. `ui-run-artifacts`' tab click leaves GLANCE mode where jsdom ignores Escape: enter Details first (`go(w, 'running/r1/details/artifacts')`).
- A global chord (⌘K) stands down while a modal is open: modals (`modalShell` → `#confirm-modal`, `#mode-modal`, `.viewer-modal`s) set no `inert`, trap no focus and listen in BUBBLE. Guard before `preventDefault`: `if (doc.querySelector('.viewer-modal:not(.hidden), dialog[open], .guide-layer')) return;` (`[aria-modal]` misses `#viewer-card`/`#folder-browser`; the Ask sheet still reaches the chord, as intended). `if (e.repeat) return;` hands a held Ctrl+K to the browser. Safari IME Enter can carry `isComposing === false, keyCode === 229`. Pin: `test/ui-topnav-search-app.test.mjs` (`#confirm-modal` unhidden, Ctrl+K then Escape, focus stays).
- A confirm opened BY an Escape handler is cancelled by that same Escape (`modalShell` adds its listener synchronously): `ev.stopPropagation()` in the opener, stand down while `#confirm-modal` is shown (Tab walks into the sheet), restore focus yourself after Cancel.
- Escape-to-close over a code editor traps keyboards (`code-editor.mjs`: Escape-then-Tab is the only way out): every element Escape handler whose subtree holds `createCodeEditor`/`paramEditorHook` output skips `ev.target.closest('.code-editor')` (incl. the selection toolbar's Params popover in `workflows/shell.mjs`). jsdom `bootShell()` passes no `highlight`: pass it.
- Chat History overlay: `ask-panel.mjs` `onDocKeydown` (document capture) `ownsKey` claims every Escape below 1100 px; each new field with its own Escape needs an exemption like `historySearchInput` (pin `makePanel({innerWidth:900})`, `test/ask-panel-history.test.mjs`).

## Stacking and pointerdown
- z < 40 in the root stacking context sits UNDER the open Ask sheet (`.ask-dock` fixed z 40; ceiling 41, phone drawer 42, modals 50+, toasts 71). Settled: `.tsearch.is-open{z-index:41}` on the popover's positioned root. Proof: an index.html copy with `<base>` + the stylesheet as `file://…/style.css` (a `/style.css` href loads nothing), append `.ask-dock > .ask-sheet`, `elementFromPoint` at each row centre.
- Ask's `onDocPointerdown` (capture) closes the sheet on outside presses and `closeSheet()` focuses `prevFocus`/the pill BEFORE the browser's mousedown focus: a popup closing on "focus outside" hides at pointerdown and the click falls through. jsdom still clicks a hidden menu: assert `menu.hidden === false` right after `pointerdown`.
- Settled (side-flyout): close only on focus that LEAVES (`focusin` with `relatedTarget` outside popup, trigger, `inside()`, submenus) and never during a press that started on it — window capture: `pointerdown` sets, `pointerup`/`pointercancel`/`contextmenu` clear (every press flag needs all three; Marketplace `page.mjs` lacked `contextmenu`). Track the last input on window: only a keyboard open holds against the 180 ms hover close.
- Settled (top bar search): its root is on Ask's allowlist (`…, .term-pane, .tsearch`). `.activity-pop` stays off it, and Activity stays open across routes on purpose (`showView` closes only `nodesFlyout`, `sideActionsFlyout`, `acctFly`; pinned in `ui-activity-app`).
- A row routing while the sheet is open lands UNDER it: `askPanel?.close(); location.hash = …`; pin with `detail:0` clicks and NO pointerdown. Safari: a pointer-opened flyout stays open when ⌘K moves focus (`relatedTarget` null).

## App code's own clicks, repaints, hover
- side-flyout treats app code's `el.click()` as "outside": `reselectHiddenDetailTabs` (on `worca:level`) and schedules-view `paintPane` close the account menu and Nodes flyout; a hover open closes a click-opened account menu. Repro: log `HTMLElement.prototype.click`, check `#acct-menu.hidden`.
- `paintRunningActions` rebuilds rows AND their scroller every `actions-changed` frame: focus put back has `relatedTarget` null, `scrollTop` resets (a click can hit another row's Stop) — keep the scroller outside the rebuild. Phone drawer: Stop/row name closes the drawer, focus `#mbar-menu`.
- No app.js boot exercises hover (`createFlyout` reads `matchMedia('(hover: hover)')` once): stub `window.matchMedia` before import (`!!width &&` guard: `null <= 760` means phone), then `mouseenter`.
- Guide hops: a `mode:'pointer'` ring/balloon (z 72/73) sits above `.nav-fly` (z 43), so `lift` does nothing; only a stacking-context ancestor traps a lift — `container-type:inline-size` does NOT.
- Re-route tests: "click again from the page it opened" passes with the branch deleted (no hashchange): assert what only the re-route produces (focus in the target card).
- Focus restore via `querySelector('#agent:planner')` throws in Chrome (jsdom accepts): `getElementById` + a `[data-focus-key]` scan.
- Chrome >= 130 makes an overflowing scroller with no focusable children a Tab stop: `tabindex="-1"` on the listbox or size the cap.
- Series plans: grep later plans for neighbouring text before adding a line; never name an element a later plan removes (`ui-id-consistency`).
