## Read CLI facts from the binary, never by spawning `claude`
Audit lanes may not spawn the real CLI. The binary (`~/.local/share/claude/versions/<ver>`, ~230 MB, target of `~/.local/bin/claude`) holds most JS in plain latin1: scan with node `indexOf` over 64 MB chunks (`toString('latin1')`, ±500 chars per hit), diff across `versions/`; literal needles only (`grep -a` and `.{0,600}` regexes time out; minified names change per version). **The floor is `docker/CLAUDE_CODE_VERSION`** (hosted image, 2.1.278 at `c2e7ab49`): check every flag form against it.
- `--agents` takes a FILE PATH only from 2.1.281 and only with `-p`; 2.1.278/2.1.280 accept inline JSON only (a path fails `Invalid --agents configuration: invalid JSON`; on `--resume` definitions drop silently). Definition `{description, prompt, tools?, disallowedTools?, model? (alias, id or 'inherit'), effort?, permissionMode?, maxTurns?, skills?}`; a Task/Agent call takes `model`, no effort.
- `disableSideloadFlags` (2.1.292): `--plugin-dir` is refused via `exitWithError` (`… disabled by your organization's managed settings (disableSideloadFlags)…`, stderr + exit 1 before stream-json init; runReal puts the stderr tail in the error so `SIDELOAD_REFUSAL_RE` sees it). The same setting makes the CLI IGNORE `--mcp-config` with a warning: a registry MCP layer is silently absent. `--plugin-dir` is a VISIBLE option: `probeClaudeCapabilities().pluginDir === false` means the `--help` probe failed (8 s timeout).
- `disableBundledSkills` (= `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS`, 2.1.289+) reads MERGED settings, so `--settings` works (`extraSettingsOf` passes it): bundled skills drop (survivors `doctor`, `design`), bundled workflows empty, `source:"builtin"` commands become user-invocable-only; plugin skills untouched. Also `skillOverrides` (on|name-only|user-invocable-only|off). Docker's 2.1.278 predates the key.
- Settings validation (`--settings` and files): the schema is `.passthrough()` (unknown keys ignored), but a KNOWN key with a wrong type drops the WHOLE source (`{settings:null}`) — worca's denies and host-guard hook with it. Every extraSettings value must be type-exact (boolean `true`). `flagSettings` and `policySettings` load whatever `--setting-sources` says.
- Skill tool (2.1.292): deny rules, then allow (`Skill(x)` exact, `Skill(x:*)` prefix), then auto-allow when every non-empty property is in a safe set, else "ask" (denied under dontAsk); MCP skills need GrowthBook `tengu_mcp_skills` and vanish under `--disable-slash-commands`. Input `{skill, args?}`, plugin skill `"<plugin>:<name>"`. The `.claude/<skills|commands|agents>` walk-up goes from the cwd up and STOPS at home (and after a git root): `~/.claude/skills` never loads through it; Ask's cwd `<home>/tmp/ask` stops at the worca home; in Docker it reaches `/`. User skills come only through setting sources.

## SKILL.md frontmatter: read `name`/`hooks`/`shell` exactly as the CLI does (`skills-registry/inspect.mjs`)
- CLI reader (needles `function SD(e){return Bun.YAML.parse(e)}`, `function Ks(`, `KKt(`, `qKt(`): BOM dropped; block `/^---\s*\n([\s\S]*?)---\s*\n?/` (ends at the first `---`, even mid-line); `Bun.YAML.parse` merges `<<`, keeps a duplicate key's LAST value; on a throw it retries after quoting plain values matching `` /[{}[\]*&#!|>%@`]|: / `` and turning leading tabs to spaces; non-map → `{}`. 64 KB cap only for untrusted skills.
- Bun-only readings: collection keys named by `String(key)`; ANY scalar key reading `<<` merges; a lone CR is a line break; `name` = `String(name)` for any non-null value, untrimmed, ignored past 256 chars. The CLI's fenced-shell regex is quadratic: P1 uses `/```![\s\S]*?```/` (time with `process.cpuUsage()` on 64 KB).
- yaml-package traps: `merge: true` drops a second source's quoted `"<<"` (use `merge: false` + a Bun-style builder); `uniqueKeys: false` + `mapAsMap` keeps a duplicate at its FIRST slot; `Alias.resolve(doc)` re-walks per call; `resolveKnownTags: true` decodes `!!binary` keys (keep `false`). yaml and Bun refuse DIFFERENT blocks; the CLI reads the retry only when BUN throws.
- Rule that closed all: read BOTH texts; badge when either declares one; mark the skill invalid when the readings' names differ (unless the other holds YAML the retry quoted), two keys of a map read as name/hooks/shell, the first reading cannot be built, or on ANY throw.
- Oracle: `claude plugin validate <plug> --json` (~0.6 s, HOME = scratch; `.claude-plugin/plugin.json` `{"name":"probe"}` + `skills/c<i>/SKILL.md`): `shell` errors appear exactly when the CLI read `shell: zsh` (echoing Bun's string); `name` errors only for a non-string name; `BUN_BE_BUN=1` does not make it bun. Keep a grid differential AND a corpus check over every real SKILL.md (a stricter reader invalidating real skills is a regression).

## Gates a new runClaude option passes
Named in: `runClaude`'s destructure, the `(brokerEnabled() ? runViaBroker : runReal)({…})` call, `runReal`'s parameters, its `stageClaudeInvocation({…})` call, `buildClaudeArgs`' destructure; a settings key also in `planClaudeInvocation`'s `buildSettingsPayload` call. `runViaBroker` spreads `{...opts}`; `agentSpawn` prepends `sudo -n -E -u <user> -- <abs bin>`; `runMock` drops argv options on purpose; no other argv builder exists. `--plugin-dir` reaches argv as one entry on inline, staged, broker and sudo paths.
- Removing a name from the destructure alone is a ReferenceError; the SILENT drop is removing it from the CALL (only the end-to-end fake-bin test catches it). The staged branch (GH #380) rebuilds argv via `buildClaudeArgs(opts, delivery)`: give each new flag a `planClaudeInvocation({prompt: 'x'.repeat(30000), …}, {dir})` row. "Merge extras first vs last" is equivalent once a key filter strips collisions: pin the exact `--settings` string.
- `RUNNER_SETTINGS_KEYS` is a DENYlist (`permissions`, `hooks`, `disableAllHooks`, `env`): a new key that can run a command or loosen permissions joins it.
- Agent-isolated spawns: pipeline dirs are `2770 worca:worca-share` + umask 0007; `materializeSkillMount` sets 0750/0640 keeping setgid. `skillHostFacts()` reads the SERVER's `~/.claude`, but an isolated spawn runs with `HOME=<agent home>`. runReal builds the rejection from STDERR only, so the sideload net also scans the first 20 `log` lines. Probe with an absolute POSIX stub as `bin` (logging argv), `env -u WORCA_MOCK`, `TMPDIR` = scratch; broker: `claude-runner-broker` `brokerFor('single')`.
