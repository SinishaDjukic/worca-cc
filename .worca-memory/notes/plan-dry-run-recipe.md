## Fence applier (node, in scratch)
- Slice per `### Task N:` / `- [ ] **Step K:`; fences verbatim, opened by ``` OR `~~~~` (a `~~~~markdown` Create holds inner ``` fences); slice `fenceStart+1 .. fenceEnd-1` and assert the last line is not ``` (else a template-literal opener: SyntaxError far below). Count ops vs op lines; throw on any other Create/Replace/Append/Modify line, counting `**Create`/`**Replace` ANYWHERE in a line (Creates inline on Step lines were skipped, faking `ERR_MODULE_NOT_FOUND` reds).
- Resolve files from the backticked path above (suffix-match `lib/yaml.mjs`); Create needs "reate" or a line that is only `` `path`: `` (a prose line ending ":" once overwrote `ui/server.mjs`); extract by the LABEL line, never `includes('`path`:')` (a "v2 changes" header quotes the same path); check each file's first-line `// <path>`. Create = fence + `\n`.
- Replace: pair the fence after "Replace (exact" with the one after "With:"; anchor exactly once; `s.replace(old, () => text)`. "Append to the end (after one blank line)" = `${s}\n${body}\n`; a bare "**Append to `f`:**" = `${s}${body}\n` (its fence opens with a blank line). The step VERB decides replace vs insert ("append one line before its closing brace" quotes EXISTING lines as anchor); a fence whose first line is already in the file is an insert — print ±6 lines around each insertion.
- Skip "Expected" fences when extracting commands. Write only via `new URL('./x', import.meta.url)`; `git status --short` before handoff. Test the applier by rebuilding a replayed tree vs HEAD; after editing the plan, replay the NEW text again.
- **Mixed prose plans:** list fences `idx line lang first-line`, hand-write an ops table `[task, 'red'|'green', op, file, F(fenceIdx) | S(planLine, k)]` (S = k-th backtick span, never retyped); dry-run in memory, apply per phase (Step 1 → 2 red → 3 → 4 green).

## Per task
- Apply in wave order, commit per task; `git add` list vs `git show --name-only`; every `test/…` in a Step 4 command exists at that commit; Step 2 on `<commit>^` + the new tests (RED), Step 4 at the commit (in a second clone); full suite once at the end, then one CLI run of the feature.
- A Step 2 extending a test file's static `import { … }` with not-yet-written exports never REDs as "`fn is not a function`": ESM linking fails the whole file `SyntaxError: … does not provide an export named …` — fix the plan's Expected.
- Commit phases with plain `git add -A` (`git add -A -- . ':!node_modules'` exits 1 on the ignored link and silently skips an `&&` chain). A loop checking out each task commit finds it with `git log <branch> --grep` (from a detached HEAD later commits are invisible) and refuses an empty sha (`git checkout -q ""` is a silent no-op).
- Fix a v(N) plan with `git commit --fixup=<task commit>` + `GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash <checkpoint>`; `git diff c^ c` per commit reproduces the fences. Never `--fixup=<a fixup sha>` (autosquash aims at the task commit; fold it with a node `GIT_SEQUENCE_EDITOR`). A tip fixup can lean on a LATER task's import (a `try/catch`-wrapped call passed every tip run and did nothing at its own task): after folding re-run EVERY task's GREEN; repair with `git filter-branch --tree-filter "node <idempotent edit>.cjs" <task>^..<branch>`; never wrap an import-dependent call in a catch.
- Phase lanes fetch the earlier lane's replay read-only (`git -C <mine> fetch -q <their>/tree replay:refs/remotes/alane/replay`; full 40-char shas). Audit "port test X" / "delete the Y assertions" prose by RUNNING it. Next cycle: keep the fence COUNT (widen an OLD), remap anchors by line text + occurrence ordinal.
- Folding reviewers' prototypes back: `git apply` every lane diff onto one clone of the replay tip; per hunk of `git -C ref diff -U6` take the largest context whose old text occurs ONCE in the plan, key hunks by `+`/`-` lines and place each once; an unplaced hunk = untouched base code → a new "Replace (exact, unique at <base>)" op. Replay, `diff -rq` vs ref.
- Probe scripts importing repo modules live IN the tree (`.worca-cc-test/<task>probe/`, or `ai-artifacts/<probe>/` while `npm test` runs); mutant strings go through a JS file (`\x27` is invalid JSON).

## Running a plan's tests with no tree (in memory)
Apply ops to `git show <checkpoint>:<file>` strings in a Map; run under `node --experimental-vm-modules` in one `vm.createContext` with `process, Buffer, URL, URLSearchParams, Intl, Blob, AbortSignal, crypto, atob, btoa, structuredClone, TextEncoder, TextDecoder, MessageChannel, performance, console` + timers; each module a `vm.SourceTextModule`; linker: relative → Map else git show, `node:*` → SyntheticModule (`node:fs` readFileSync overridden for repo paths, `node:test` a collecting shim), jsdom via `createRequire('<real checkout>/package.json')`. Count `uncaughtException`/`unhandledRejection`; trust only the diff of failing NAME sets vs an empty Map (harness-only reds: `(t)`/`t.mock.timers`, in-process server, markdown bundle). Stop at Task N's Step 3 (RED) and Task N+1's heading (GREEN). A step runner must not prefix the plan's command (`env -u X ${cmd}` over `h=$(mktemp -d) && HOME=$h …` made `h=…` an env argument: tests ran with `HOME=''`) — check one command prints the mkdtemp HOME; a red a direct run never shows = suspect the harness.

## All-green is not verified
- Mutation sweep: one node script over `[label, file, find, replace]` — write mutant, run a fixed test list, restore, print RED/GREEN (~40 × 200 tests ≈ 10 min). Each GREEN is an unbound line (the plan's `(C)` notes likeliest) or a test whose NAME lies (an index "from the DDL" stayed green with the DDL line deleted: gap repair recreates it). Then adversarial probes per front (server/run path, UI, catalog/CLI; spawn/stream code with pathological input). Killer tables: `[{ id, file | edits[], from, to, tests }]`, each anchor once. A guard OR'd with another arm dies only by a fixture reaching it through that arm alone (seed `private HttpClient _http = new HttpClient();`, not `…_http;`).
- Mutant runner traps: a killer catching a HANG reports `ℹ cancelled 1` (give `{ timeout }`, count cancelled as killed); a SYNC hang ends only by `spawnSync({ timeout })` and its grandchildren outlive it (a route opening a terminal left `tools/test-run.mjs`, `node --test`, `zsh -i` at ppid 1: find them by your scratch path in `ps -ax -o pid,ppid,command`, `kill <literal pids>`) and the file's `after()` never runs: remove its `worca-…-` mkdtemp dirs by exact name, never by prefix. Piped Node 22 prints TAP (`# fail 1`): judge `r.status === 1`, never a `ℹ fail` grep (exit 2 = `tools/test.mjs` refused a flag, no kill).
- A CREATE/PATCH field builder omitting falsy keys cannot turn a flag OFF (`scheduleRequestFields` dropped `sourceFromPrevious: false`): drive every boolean OFF through the real store. Exclusion filters survive fixtures holding only the feature's own rows: seed one UNRELATED row per filter. Destructuring defaults make some survivors equivalent (`{ expectSha = null }`: `!= null`→`!== null`).
- **UI controller plans: race them on the real app.js boot.** Classes: a baseline re-read from the form AFTER an awaited PUT drops edits typed meanwhile (store what was sent); a run over targets fixed at its start ignores ticks taken back mid-run; a close whose opener left with the reload drops focus to `<body>` (`createSheet`'s `onClose` fires on hand-offs too and runs before focusBack: the fallback goes there). Holds and late opens are ENUMERATED per path: a Save hold covers every control rewriting the saved group; EVERY open after an await needs `dialogOpen(doc)` + the `#marketplace` hash check.
