Green replays hid blocking bugs in these classes. On any store change: a hand-edit fuzz (every file x nesting level x exported op) throws nothing but `McpStoreError`, and every crash-window prefix of the multi-file ops shows no violation. fs/rm/copy guards and `git archive` bounds: [[plugin-update-apply-traps]].

## Store
- **Lenient read + orphan sweep = data loss:** inside `withMcpLock` a file read as an empty map becomes the snapshot and the sweep deletes secrets/tests of "gone" sets (a trailing comma in `sets.json` wiped `secrets.json`). Inside the lock an untrusted read THROWS (unreadable; `servers`/`sets`/`secrets` unparseable — only `tests.json` may be replaced; a top-level key of the wrong type). Open: a DANGLING `sets.json` symlink reads ENOENT — `lstat` and throw if the path exists. Strip a leading BOM first.
- Skills P1 contract: `readSkillLibrary()` returns `{newer, damaged, skills}`; an untrustable `library.json` (bad JSON, non-object, `skills` not an object, dangling link) makes every write 409 "…is damaged — fix it or remove it" and is never replaced. Readers call P1's `skillMdFields`, never `yaml.parse`; `skillNameProblem`/`isValidSkillFolderName` take any JSON value; unreadable files are a skill's problem, never a throw out of `loadSkillCatalog`. P7 routes pre-check leniently (404) and add name-taken advice to every 409.
- Dropping a junk owner loses its invariants (a junk set entry never retired: `createSet` reissued its id with the old assignment). Liveness is per (set, server); Team sets need Team state. A suffix loop can walk into a reserved prefix (`team-2`): re-check after suffixing. `readMcpStore()` hides orphans: prove removals on the raw file. Branch on id kind, not truthiness (home `''`).

## Resolvers and screens
- What P1's screens admit, the resolver must survive: a lone surrogate passes `textProblem` and `encodeURIComponent` throws `URIError` out of `resolveMcpServers` (`toWellFormed()`). A text round trip keeps url[0] a ref WITH its affixes: compare the stored DEF too.
- A value screened alone is not the joined result (`deploy:pw@host` behind `https://`): re-run write-time screens on EVERY materialized string (url, args, env, headers, names) and parse every `scheme://` substring; a stand-in parse that skips its check on failure is a bypass.
- Probe the real resolvers with no disk: consumer tests inject fakes, so inject wrappers over a hand-built snapshot — `resolveSkillRegistry(opts, {readStore: async () => snap, loadSkills: () => catalog, hostFacts: () => ({installedPluginNames, sideloadDisabled})})`; `resolveMcpServers({...opts, store:{catalog:[], bases:{}, sets, teams, projects, secrets:{}, tests:{}}, env:{}, platform:'darwin', execPath:'/n', worcaRoot:'/w'})`. Snapshot `sets: {general:{name,members:[],skills:[]}, <id>:{name, slug, members:[{server,enabled}], skills:[{skill,enabled}]}}`, `teams`, `projects:{<key>:{sets, includeGeneral}}`; catalog rows need `id, name, dir, valid:true, pluginEnabled:true`. Feed the real picker from `askMcpPreview(...)` keyed by `JSON.stringify(body.mcpOff)`.
- Facts consumers re-derive wrongly: `resolveSkillRegistry` already returns `blocked` ('sideload-disabled') and `newer`; every `skipped` row carries `pluginName` + `qualifiedName`. `cachedTeamFor` returns `{home, required, requiredSkills?}` (both resolvers share `collectSets`). `teamSkillRows` vs `resolveSkillSets` differ only on the per-spawn cap (24) and `blocked`. `mcp-run-picker.mjs` exports `mcpSkipView` AND `skillSkipView`. `skillHostFacts()` never throws.
- Plugin names: never the single-set `pluginNameFor(set, installed)`; P3's `pluginNamesFor(sets, store, installed)` names every PERSISTED set in id order (`Shop` + `Shop set` → `shop-set-2`). Probe `buildSetView(ctx, id).set.pluginName` vs `resolveSkillSets(...)` on one snapshot.

## Untrusted text: throws and quadratic time
- A plain JSON object throws when coerced: `{"toString":0}` in a template literal, `String()`, `+ ''`, `join`; `${x ?? ''}` guards nothing. Compare after `typeof`; `express.json` bodies too (a 400 became a 500). `String(['tok'])` passes `FIELD_KEY_RE`. `arr.push(...other)` throws RangeError near 120k items.
- Values ~2100-2900 deep parse and stringify, but `canonicalJson`'s recursive `norm` throws a raw RangeError: fuzz depths 2000-3000.
- V8 regex stack overflow on one long run: `[cls]{40,}$`, `sk-[cls]{16,}` (any `{n,}`, n > 0) throw near 5.6M chars, a repeated group near 6.7M; `[cls]+`, `\S+`, bounded `{0,31}` are safe. Reachable (JSON limit 8mb, Ask 64mb): trailing `{16,}` in `.test()` = `{16}`; `^[cls]{40,}$` = length check + `s.search(/[^cls]/) < 0`; cap id regexes with `(?=.{1,1024}$)`. An Express 4 async handler throwing before its `try` exits the server.
- Quadratic: unbounded repeats before a literal (`/[A-Za-z][A-Za-z0-9+.-]*:\/\/\S+/g`, killer `'a.'.repeat(75000)`); `TOKEN_SHAPE_RE`'s JWT arm per `\beyJ`; `includes()` per item per component; `/\/+$/g` (use `/(?<!\/)\/+$/`). Time every screen on 150k chars of `'-eyJ'`, `'a.'`, `'://'`, `'a:'`, whitespace and 10k+ refs (< 2000 ms, as `test/mcp-literal-screen.test.mjs`).

## Git URLs: git reads them unlike WHATWG `URL`
- Stored-URL rules: http(s) has no user name; no password, query, fragment, user decoding to `u:pw`, or token-shaped user; scp-like holds one `@` and no bracket; URL <= 4096, folder <= 1024. No `%` before the path of a `scheme://` URL (git decodes before splitting user/host: `ssh://evil%2F@github.com/r` reaches evil); git ends an `ssh://` host at the first `/`.
- `new URL(url).hostname` is not the host git contacts (`file://github.com/p`, non-ASCII, `https:///h/r`, backslash userinfo `CORP\jdoe:pw@host`): refuse backslashes or read raw userinfo to its last `@`. Offline check: `git -c 'credential.helper=!f(){ cat >&2; echo quit=1; }; f' credential fill`. curl sends `%2e%2e`/`%2F` unchanged, so a checked `pathname` is not what git fetches (`planClone` rebuilds `https://host/owner/repo.git`).
- Hosted "no server folders" covers git sources: `checkGitSource` accepts `file:///path` and `file://localhost/x`; hosted = https only (`planClone` + `WORCA_CLONE_ALLOW`) on import AND the update preview's stored origin. Harness: `test/api-skills-hosted.test.mjs` `before`, `TMPDIR=<mkdtemp>`.
- Which host git contacts, no network: a 127.0.0.1 `net` server answering 403 as `HTTPS_PROXY`/`https_proxy`/`ALL_PROXY` (unset `NO_PROXY`); per transport `GIT_PROXY_COMMAND`, `-c http.proxy`, `GIT_TRACE`, `GIT_SSH_COMMAND`. Mutant runs block git with `GIT_ALLOW_PROTOCOL=file HTTPS_PROXY=http://127.0.0.1:9 GIT_SSH_COMMAND=false` (never under `npm test`); probe ssh as `ssh://git@127.0.0.1:1/x`, never a real host.

## Probe recipes
- `WORCA_HOME` is the PARENT of the store (`worcaHome()` = `<WORCA_HOME>/.worca-cc`): build paths from `mcpDir()`, `skillsDir()`, `pluginsRoot()`, `pluginsLockFile()`; set a fresh mkdtemp before a dynamic `import()`; simulate crash windows by writing the state the first write leaves.
- Fail every MCP-locked write without patching: write `{...json, schema: 2}` into `<worcaHome()>/mcp/sets.json` (409 "need a newer Worca" before `fn`; readers still work). Fail inside a flow: `node --experimental-test-module-mocks` + `mock.module(storeUrl, {namedExports: {...real, x: failing}})` before importing the consumer.
