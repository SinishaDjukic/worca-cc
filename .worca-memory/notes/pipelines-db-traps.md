## Schema gap repair (`src/core/db.mjs`)
`repairSchemaGaps(db, gaps)` runs `addColumns()` → tables → `addColumns()` → indexes; every rung from v12 and `reconcileSchema` funnel through it inside `getDb()` — a throw means the app does not open for every checkout sharing `~/.worca-cc`.
- A new INDEX on a new incremental COLUMN throws `no such column` inside a table's own `IF NOT EXISTS` DDL block (`SCHEDULED_RUNS_DDL`, `ASK_DDL`): `INCREMENTAL_TABLES` keys share one block, so a home missing ANY sibling re-execs it over the column-less table — the leading `addColumns()` pass makes that safe (the two calls are NOT redundant); `INCREMENTAL_INDEXES` is always safe. Test by dropping a sibling table (`DROP TABLE notifications`) plus the new column/index, then `migrate()`.
- Placement: a `SCHEMA_V1` base table (`pipelines`, `workspaces`) gets new columns in `INCREMENTAL_COLUMNS` ONLY; an `INCREMENTAL_TABLES` block needs its DDL AND `INCREMENTAL_COLUMNS`. Post-v1 `pipelines` columns live only there (grep first); `pipelines` has no `run_dir` and no `created_at`. `DROP COLUMN` fails on indexed/PK/UNIQUE/FK columns.
- Test a rung with a `RUNGS` row in `test/db.test.mjs` (`{v, cols:[[table, col, valueOnExistingRow]], tables, indexes}`; indexes naming a dropped column FIRST), never a new `db-migrate-vNN` file; add the fresh-DB assert to N1 and a `HOST_ROWS` insert for a new host table. Two count pins redden: the ladder `rows.length` (+2 per rung >= 25) and `test/ask-db-schema.test.mjs` (exact `ask_threads` columns). Probe (~3 min): `git archive HEAD` scratch + link, `env -u WORCA_HOST_PID WORCA_HOME=$(mktemp -d) node --test test/db.test.mjs test/db-migrate-*.test.mjs`.
- Exception: a rung that BACKFILLS data on the ladder only (V69 `projects.vcs`) gets its own `db-migrate-vNN` test: column on a fresh DB; `DROP COLUMN` + seeds + `PRAGMA user_version = N-1` + `migrate()` twice; a minimal hand-seeded DB still reaches `SCHEMA_VERSION` — gate the backfill on `hasSqliteTable` + `table_info` and fence it in `try {}`.
- Merging dev into a long-lived branch where both took the SAME rung numbers: keep dev's; move the branch's rung after dev's last (`SCHEMA_VERSION`, `applySchemaVNN`, its `if (current < NN)` LAST, comments, docs/storage.md), re-save its test as `-vNN` with seeds at NN-1, grep the diff for the old number. A home stamped by the old branch build skips dev's same-numbered rung forever — safe only for DDL also in `INCREMENTAL_TABLES` (a skipped DATA rung is lost). Prove: `migrate()` a node:sqlite file with the old then merged db.mjs and diff `sqlite_master` + every `table_info` against a fresh merged DB.

## Fixtures that read rows
- A run dir is never a column: `runDirForRow(row)` scans `<store>/<key>/pipelines/` for a `-<id>` basename. Seed with `seedPipeline`/`seedWorkspacePipeline` (`test/helpers/db-seed.mjs`), files under the returned `dir`; a chosen id via `seedPipelineRow({id, projectKey})`.
- The ledger holds two harness rows (`preflight`/`done`, agent_key null, exec_kind `'cycle'`): select by `node_id`. Verdicts are `reviews.verdict` rows, never artifacts. Truth check: `new DatabaseSync(join(homedir(),'.worca-cc','worca-cc.db'), {readOnly:true})`.
- `readStepQuestions` rows are pinned by exact `deepEqual` and ride History/`get_run_progress`: a new row kind's field is CONDITIONAL (`...(form ? {ask, formAnswer} : {})`).
- `DEFAULT_RUN_ROOT_MODE` is `'detached'`: loop probes over `WORCA_RUN_ROOT = 'detached'|'legacy'` with an empty mkdtemp `WORCA_PROJECTS_ROOT`. A parked run's step stays `paused` in `pipeline_steps`: settle-from-row paths map it.

## Archive and terminal state
- `DELETE /api/runs/:id` is an ARCHIVE: `archivePipeline` stamps `archived_at`, removes branch, worktree, run root and artifacts; `status` stays; a live run is refused (409); UI verb **Archive**. Logic reacting to "gone" reads `archived_at` first; pickers filter `archived_at IS NULL` (`after-candidates`, `/api/branches`, `artifacts.mjs`). Archive also refuses retained work: DB records (`retainedWorkFor`, `checkoutRecordsFor`) OR run.json `retain.members[]` with a live `worktreeDir` (teardown writes run.json first, the DB stamp last) — a route acting before archiving asks both (`archiveKeepsWork`) or acts then 409s.
- Run chains' `after` has three shapes: `ticket.after` `{kind, id, policy}`; `resolveAfterRef(…).after` adds `title, status, pipelineId`; `afterRefOf(id)` adds `projectKey`/`workspaceId`/`scheduleId` — a card needing the title carries the resolver's answer.
- A settled `runs` Map entry stays `paused` forever (Archive and Restore never touch it; `settleStaleParked*` settle only done/stopped/error): judge paused from the ROW (`status='paused' AND archived_at IS NULL`, what `claimPausedForStop` claims), the Map only for other statuses and `isFinishingRun`.
- A sentinel time leaks into every reader: waiting after-tickets sit at `run_at = 9999-12-31` — grep `runAt`, `run_at`, `whenOf(`, `beforeOnce` in `src/cli`, `src/core/ask`, `ui/public`.
- `results.json` = the frozen line counts History prefers (`diffFrozen`; live `diffShortstat` is 0/0 after merge). `_buildResults` writes it on done, on stopped/error only when something changed, mid-run on an ERROR pause only; workspace runs `{summary: rollupSummary(perProject), perProject}` (`Number.isFinite`). `artifacts.mjs` has its own `RESULTS_FILE`. Prove with a temp repo merged `--no-ff`.

## run.json
`writeRunManifest` REPLACES the file (only `updateRunManifest` merges, `{...cur, ...patch}`): `_setupRunRoot` writes the minimal manifest after every member is set up, so a `_recordRunWarning` before it is lost (record setup warnings AFTER it); `assembleRunContext` rewrites `warnings` keeping only `FOLDER_COPY_WARNING_RE`/MCP lines. Removing a key: `delete state.x` is not enough — teardown's `copyRunManifestTo` makes it durable; pass `{key: undefined}` (only when present, to stay byte-identical); prove with `readRunManifest(runRoot)`.

## Races (claims)
- Check, awaits, write is NOT a claim: `_resume()` awaits rehydrate/guardrails/policy/checkout/prompts before writing `running`, so another process's stop lands in between. Only a conditional `UPDATE … WHERE status …` serialises: `claimPausedForStop` / `claimForResume` (`NOT IN ('stopped','done','error')`). Probe: two harnesses from `readPipelineForResume(id)`, one resumer awaiting while `stopper.stopPaused('x')` runs.
- Teardown runs AFTER `done`: `isFinishingRun` covers checkout only via `!entry.settled`; register in-flight work there (`STOPS_IN_FLIGHT.has(id) ||`). A CLI stop is invisible to the server. Probe: wrap `RunHarness.prototype._teardownRunRoot` to await a gate.
- A claim making the row `running` must start ownership: `_startHeartbeat()` right after `this.pipeline = …` in `_resume()`, plus `if (this._rehydrated === false) return;` in `_checkControlSlot`. Probe: hook `_resolvePolicy` to enqueue `stop`/`pause`, wait 2.5 x `CONTROL_CHECK_INTERVAL_MS`.
- A crash between the claim and the first `_persist` credits downtime as active time and turns a paused row `interrupted`. Last-resort catches that `_persist` wipe the row: `_stopPaused`'s inner catch (0 steps/$0) and `_engineRehydrate` throwing post-claim (settles `stopped`, worktree uncommitted).
