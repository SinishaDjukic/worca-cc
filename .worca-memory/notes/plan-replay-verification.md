Running tests: [[pipeline-worktree-node-modules]], [[headless-background-suite-run]].

## The plan port can name a file never written
A refiner whose lanes outlive the 600 s headless background ceiling ("Background tasks still running after 600s; terminating", often then `[Request interrupted by user]` — not a user waiver) writes neither plan nor verdict; the engine logs `verdict file missing: … — treated as clean` and binds the port to the next `-vN`.
- Confirm: `ls <store>/plans/<slug>*`; `grep 'verdict file missing\|treated as clean\|draft generated' <pipeline>/live-log.ndjson`. Implement the newest EXISTING `-vN`; record the substitution in `<pipeline>/DEVIATIONS.md` and every task file. "draft generated" = a draft in the dead refiner's `/private/tmp/rf*` scratch: replay it; if anchors, RED and GREEN hold, copy it to the port path and say so.
- Reviewing after a dead cycle: byte-identical + green is NOT clean — re-run each `refiner ▸ Probe …` repro on the worktree, block on the real ones.
- Reviewing a FIX cycle of a decomposed run (old scratch gone): run each `tasks/*.md` applier's read-only `check` step in the worktree (DRIFT = files the fix touched), every task's `red`/`green` in a checkpoint clone (= the plan tree), then `cmp` both trees over `git diff --name-only` and `diff -u` the rest: that is exactly the fix. Fixing after the port moved to a newer `-vN`: never hand-port — replay the new plan and the task files into two clean base clones; per file, tree = old replay → take the new one, else `git merge-file -p <tree> <old> <new>`; mutation-test each merged-in rule.
- As refiner: copy the input plan to the output `-vN` FIRST; dispatch audit lanes with `run_in_background: false`, all in one message (still concurrent); replay first, then point lanes at `git clone <scratch>/tree` so they need no applier. A resumed refiner gets the NEXT `-vN`: write to the resume prompt's paths, `cmp` + unlink your stale copy. Dead lanes leave scratch: re-dispatch fresh lanes naming it. Sub-agents cannot write `REPORT.md`: take the report as their final message.
- `docs/superpowers/` is gitignored: a run worktree has no specs or sibling plans — read the real checkout (run-root CLAUDE.md "real directory").
- Sub-agent quotes are not anchors (a fan-out report indents quoted lines by 2): re-read each region before replaying.
- Look for an earlier run of the SAME request first: `ls -t <store>/plans | head`, sibling `pipelines/*<slug>*`, `git branch -a --list 'worca-cc/*'`. Re-verify its plan by replay, never by its status line (one said "suite green" over `ℹ fail 6`). The cycle-1 output overwrites the old v2 (back it up); its gate sha names the OLD checkpoint — rebase it.

## Verify by replay, never by reading
Plans claiming "every block exact at the base" still hold dead anchors (a dropped trailing `// …` comment; a fence ending in a blank line the file lacks), each halting the implementer under the stop rule. A clean replay still misses methods inserted by replacing `  async fn(…` (they land between fn's JSDoc and fn — anchor on `  /**`) and a field a route stores and uses in one request: add a read-only spec+code audit lane.
- **Base = the CHECKPOINT** (run-root CLAUDE.md), not the plan's "base". Run `git log --oneline <checkpoint>..HEAD` first: HEAD can be AHEAD (a re-run on a previous pipeline's branch that already implemented the plan — never re-apply; turn the plan into a continuation closing `pipelines/<prev>/impl-review-cycle*.json`). A Task 0 `git switch -c <branch> <base>` drops later commits (and fails in a run worktree): stay on the branch.
- Scratch, never the pipeline worktree (`git worktree add` touches the real repo's metadata): `git clone -q --no-checkout <worktree> <tmp>/tree && git -C <tmp>/tree checkout -q -b replay <base>` under a realpath (`pwd -P`: the no-real-claude guard compares `$PWD` with it); deps per [[pipeline-worktree-node-modules]]. A clone has only HEAD: `cp -p` the `git status --short` files over and `cmp`.
- Replay with a node applier ([[plan-dry-run-recipe]]), `node --check` after every patch; never retype a "verbatim" fence — extract and `cmp`. All-green is not verified: mutation-check every new rule.
- **Implementing a prose-heavy task whose task file names a refiner prototype:** `git -C <proto> log --oneline <checkpoint>..HEAD` — early commits ONE PER TASK (subject = the plan's commit message), later `combined: vN` fixes (find yours with `git log -S '<rule text>' -- <file>`). Confirm `git diff --stat <checkpoint> <c>^ -- <files>` is empty, `git apply` (never `--index`) the task commit's diff for your files, then each fix commit's hunks IN ORDER; one read-only audit lane checks every Files bullet / Step 3 paragraph against the diff.
- **Patching a plan without retyping code:** locate all OLD anchors first (non-overlapping), splice from the end; lift code byte-exact by first/last-line markers; keep prose OLD/NEW pairs in a delimiter file (`@@OLD/@@NEW/@@END`), never JS literals (`\x00`, `${`, backticks). Apply once by node (never re-Write the plan), replay the patched text, mutate every new line. Before patching an upstream plan, grep downstream plans for `Replace|Append|Modify` of its files and for fixtures writing its data files.

## Series plans: prove the predecessor landed
- Before reviewing snippets confirm its files exist (`ls`, `git log --all --oneline -- <path>`). Absent → critical: a Task 0 stop-gate, and check contracts against its PLAN TEXT (author checkout `docs/superpowers/`). "Absent" can mean a sibling pipeline branch (`git branch -a --contains <sha>`, `git merge-base --is-ancestor <sha> HEAD`): the absent arm is `git cherry-pick --no-commit <sha>` + a DEVIATIONS note.
- A gate's grep matches the export keyword (`grep -n "export \(async \)\?function <fn>"`; on empty, `grep -n "^export" <file>`); reconcile silent no-output checks with `git diff --name-only` ∪ untracked.
- Landed code drifts from its plan text: open every "Consumes:" signature and its tests; diff each "replace this line" fence's claimed original against landed text. It may already have done your "add" step (a second `import` is a SyntaxError, a duplicate config key a no-op); shipping its feature in a built-in reddens "no built-in declares X" pins; an "optional" predecessor can hide behind a prefix-matching pin (pin full sentences); a newly valid enum value reddens tests using it as the invalid fixture. Re-derive pinned counts/markup on the run branch.
- **Refining an UPSTREAM plan:** count each downstream backtick span / fence line in base vs your composed tree for every file you touch (only base ≥1→0 and 1→≥2 matter), then replay the downstream's seam task on your tree. Spans miss behaviour seams (a downstream task adding `span.mk-live-dot` to a helper two tasks before its CSS reddened an "every mk- class has a rule" test): apply each downstream edit of a helper your tests render, then run YOUR test files. `tools/test.mjs` never isolates TMPDIR: rm a downstream test's leftover mkdtemp fixtures by exact path.
