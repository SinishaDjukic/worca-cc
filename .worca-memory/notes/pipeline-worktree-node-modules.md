## No node_modules in a run worktree
A run worktree (`~/.worca-cc/runs/<id>/repos/<key>`) has NO `node_modules`: anything importing `ui/server.mjs` (express, ws) or jsdom dies `ERR_MODULE_NOT_FOUND` (~900 reds, e.g. `Cannot find package 'htmlparser2'`) while core suites pass — not your change. `ls -ld node_modules`; `grep -c ERR_MODULE_NOT_FOUND` a red log first.
- **Link:** `cmp` the real dir's (run-root CLAUDE.md) `package-lock.json` and `package.json` with yours, then `[ -e node_modules ] || ln -sn <real>/node_modules node_modules` (gitignored). Parallel siblings: BSD `ln -s` racing an existing link creates `node_modules/node_modules` in the real checkout — use node `fs.symlinkSync(real, 'node_modules')`, ignore `EEXIST`. A worktree with a real `node_modules` (a Task 0 ran `npm ci`) is complete: link clones to it. Remove a link with `node -e "require('fs').unlinkSync('node_modules')"` (`rm node_modules` is refused).
- **A branch that ADDS a dependency:** `preflightDeps()` exits 1 at `ui/server.mjs` import. `npm install`/`npm ci` in the worktree or clone (npm REPLACES a symlinked `node_modules` with a real dir); after such a merge the real checkout needs `npm ci` before a run may link it. `test/wsmap-deps.test.mjs` pins the WHOLE `dependencies` key list (sorted `deepEqual`, one comment line per dep): the task adding a dep adds it there too, else the only red is in the full suite.

## Running tests
- **`env -u WORCA_HOST_PID npm test`** (else `test/host-guard-wiring.test.mjs` fails one case), from a realpath (`pwd -P`, `/private/tmp/…`), never via `/tmp`. Never two full suites at once (timing pins flake).
- **Subsets: `env -u WORCA_HOST_PID node tools/test.mjs <files>`** — hermetic HOME + WORCA_HOME per call plus the no-real-claude guard. A bare `WORCA_HOME=… PATH=<guard>:$PATH node --test` keeps the REAL HOME: batching `api-run-engine-default` with `api-run-auto` / `api-memory-defrag-model` / `api-schedules` then times out its humanInLoop and wf_auto-workspace cases (~185 s each), even at the checkpoint, though each passes alone. Write plan Run lines with the runner. It takes only `--tier/--shard/--concurrency/--write-timings/--related/--base`: any other flag (`--test-name-pattern`) exits 2 `unknown flag` with no `ℹ` lines — pass whole files.
- **Waiting (headless):** a full run (~9 500 tests) takes ~370 s. Background Bash `npm test > log; echo exit=$? >> log` (a `( … ) &` wrapper reports "completed" at once), log OUTSIDE `.worca-cc-test/` (`npm test` deletes it); wait with a FOREGROUND `node -e` poller (5 s `setTimeout`, exit on `^ℹ fail` or `exit=`, give up ~560 s; Bash timeout 600000). Monitor and inline `sleep` loops are refused. Host-, load- or Node-22-only reds: [[headless-background-suite-run]].
- `test/timings.json` is read with a silent `{}` fallback: `JSON.parse` it after a hand edit.

## Task files' commit steps vs "Commit nothing"
Task files copy the plan's `git commit` step and "`git log --oneline <checkpoint>..HEAD` should show N commits; if wrong, STOP". The implementer prompt's "Commit nothing" wins (the orchestrator stages and intent-to-adds): the count is 0, do not STOP. Confirm earlier phases with `git status --short` / `git diff --stat`, skip the commit, append one `DEVIATIONS.md` entry per phase (absolute pipeline path, append-only) naming the plan's `git add` list and message plus shared files holding earlier phases' hunks — unless the task file says the skipped commit gets no entry (the task file wins). "N/N" counts quoted from later plan versions can include tests a LATER task adds: trust the step's own "PASS, 0 fail".
- Conflict-fix runs (`conflictBrief`: "run `git merge --no-ff <ref>` … and commit the merge") vs "Commit nothing": `git merge --no-ff --no-commit <ref>`, resolve, `git add` the conflicted files, leave `MERGE_HEAD`. Teardown `_commitWork` (`git add -A` + `git commit -m`) concludes it as the two-parent merge; it never checks for markers (`add -A` marks them resolved), so `git grep -nE '^(<<<<<<< |>>>>>>> )'` and `grep -n '^=======$'` per file first. Preview with `git merge-tree --write-tree -z --name-only --no-messages HEAD <ref>`.

## zsh — the Bash tool runs zsh; run every plan shell line in zsh
- `kill $VAR` makes the host-guard hook reject the WHOLE call: `process.kill(pid)` from node or `kill <literal pid>`. `rm` on a command substitution (`rm -r "$(dirname $A)"`) refuses the whole call, earlier `&&` steps included — `rm` a variable or a literal.
- `$?` after a `$(…)` in the same word is the substitution's status: `cmd; e=$?; echo "exit=$e"`.
- Each plan step is a new Bash call: variables from an earlier block are EMPTY (`/base.log` on read-only `/`; a "prints nothing" check passed on a broken run). Re-derive per block or write to a known file; judge "prints nothing" by exit status too.
- No word-splitting: `$CLI args` fails — use a function, redefined every call; loop `for n in ${=ORDER}`. `$PWD` in a function body resolves at CALL time: capture `CLI=/abs/path` before any `cd`. Run `graphify` from the repo root. A file list as a zsh array (`files=(${(f)"$(grep -l …)"})` or `${(f)"$(cat list)"}` as runner args) is refused unrun ("could not be checked for dangerous rm operations"): build the list and `spawnSync('node', ['tools/test.mjs', ...files])` in one node script (delete the three env keys from its `env`).
- `$path` is tied to `$PATH` (`while read -r hash path` empties the search path: name it `file`). A word starting with `=` expands (`echo =====`): quote it. `$VAR:path` applies history modifiers (`$T10:ui/x.mjs` → `:u`, after a `>` already truncated the target): write `"${T10}:ui/x.mjs"`; guard restores with `[ -s file ]`.
- An unmatched glob aborts the command (`--include=*.mjs` → "no matches found"): quote globs or use Grep. A parse error kills the whole call: chain with `&&`, never `;` after a step that can fail (`set -e` ignores a failure piped into `| wc -l`).
- The cwd resets to the real worktree every call: a helper writing relative paths without its own `cd` in the SAME call edits the real checkout — end such calls with `git -C <worktree> status --short`.
- Quoting: zsh eats `${…}` inside `perl -e` — patch with node; apostrophes via `<<'EOF'`; never pass a quote or a backslash-u through a Bash argument — write anchors to a file. A heredoc copied from a markdown LIST item keeps its indent and `   EOF` never ends it (zsh swallows every later line, exits 0): heredocs at column 0. A paste block with a trailing `# …'s …` comment hangs an interactive zsh at `quote>`: check with `zsh -f -i < block.zsh`.
- A backslash-u escape typed into a heredoc, Write or Edit can land as the RAW character (an invisible BOM in a regex passes every test): lift such lines from the plan with node, `od` them, and compare byte scans with the checkpoint, never absolutes (`src/shared/team-metrics/aggregate.mjs` ships a BOM, `src/cli/worca-cc.mjs` two U+2026 escapes). Read a base via node `execFileSync('git', ['show', …], { maxBuffer: 1 << 26 })` (`ui/public/app.js` is ~1.3 MB).
- `s.replace(anchor, text)` expands `$'`, `` $` ``, `$&`, `$1`: always `s.replace(anchor, () => text)`, then `node --check` in the same call.
- Edit drops a trailing space of `new_string`; Write strips trailing spaces on every line: never end an anchor on whitespace; `git diff -U0` every patched line.
- macOS: `grep -E` never matches a multibyte char in an alternation; BSD grep has no `-P` (exit 0 when piped); `[ \t]` is a literal backslash or `t`; no `cat -A`; no `timeout` binary (use the Bash tool's timeout). Scan in node.
