## Composer cards on the Chat page
- app.js composer actions are inert off the Workflows view: `wfvChatActions().libraryHas` reads `gvAgentsAll`/`gvScripts`, which only `gvLoadAgents()` fills, and it returns while `gvComposer` is null (`reloadRegistry`, `invalidateAgentCaches()` likewise). A Chat host reads `GET /api/agents?all=1` and `GET /api/scripts` itself; `saveAgentDraft`/`saveScriptDraft`/`openAgentDraft`/`openScriptDraft` work anywhere.
- The cards route picks the composer branch by card TYPE (`isComposerCard`), not thread mode: Ask-only behaviour for build/draft cards needs its own branch BEFORE it (`thread.mode !== 'composer'`); `composerCardPatch` 400s states outside `TRANSITIONS` (`workflow-build` has no `saved`) and starts no turn.
- `POST /api/run`'s `askCardId` link checks only `state === 'proposed'`, never type: any proposed draft/build card starts a run and flips to `started`. A draft saved from its card is stamped `by:'ui'`.
- A draft's KEY is its identity (Save, Save & add, `then` ops, build cards): any editor the card opens saves under that key (a wizard rename made a second agent). D12: an older card of a re-drafted key renders `superseded` (Decline only, never swept, stale Save refuses); the library holding a key stands for a card only if no OTHER card saved it (`savedFrom`). `buildCard` reuses the element while `block.state` holds: a view depending on OTHER cards needs the `view` cache key, a re-draft in a later row leaves the older card live until `ask-done`, and a re-render test must push into the SAME row. A view showing 'saved' before its record lands stays so after a failed POST. Wizard saves carry no card id.
- Card DOM: `ui-workflows-chat` regex-pins `.wfc :is(.wfv-btn,.wfc-link)[aria-disabled="true"]{opacity:.55;cursor:default;}` — add a separate `.ask-ccard` rule, never widen it. `relayoutCards();\n    applyPin();` occurs twice in `ask-panel.mjs`: anchor flush edits on `if (st.runPoked) repaintProgressCards();`. Work hung on `flush()` runs per rAF while streaming: back off fetches on FAILURE too (50 flushes = 100 GETs). `openPage` → `stale()` resets `lib.tried`; a `flip` carries `e.body` (a 409's `scriptNodes`); `makePanel({resizeObserver:true})` proves `dispose` (`.disconnected`).
- Seeded cards' mock event turns propose a run only on a thread WITH context: `updateThread(id, {context:{projectKey}})`. Fast mutants: a subset file = the test's head + its composer section (~40 s vs 807 s).

## Saving a graph
- `saveGraphWorkflow` → `validateForSave` throws `INVALID_GRAPH` on ANY `validateGraph` error, `incomplete` ones too: a "save as proposed" flow refuses `todo > 0` before showing a card (the composer allows todo only because the user finishes on the canvas).
- Script confirmation (D18): built-in `shell`/`js`/`py` place `command`/`code` params verbatim; the "Create and run scripts" switch gates `save_script`/`test_script`, not placement. Build returns `listScriptNodes(tpl, work.scripts)` → card `scriptNodes`, NEVER cut; the card posts what it SHOWED as `acceptScripts:[{nodeId, params}]`; `saveGraphWorkflow(…, {confirmScripts:true, acceptScripts})` re-derives over the real registry and 409s `SCRIPTS_UNCONFIRMED` unless `scriptNodesConfirmed(shown, derived)`. A confirmation binds to WHAT was shown, display included: pin "every row rendered" with > 40 rows. Import keeps its boolean.
- `writeGraphWorkflow(tpl, {rejectCollision:true})` throws `ID_TAKEN` only for ids the store MINTS; a body with a legal id is an upsert (`saveGraphWorkflow` keeps the body id). Pre-minting with `mintAutoWorkflowId(name, exists)` races (awaits between mint and write): two same-named saves both mint `wf_<slug>`, the second overwrites, both cards record one id (`saveWorkflowCard`, Ask `saveBuildCard`); their `ID_TAKEN` branches are dead. Repro (~2 s): `Promise.all` of two mints, then two parallel saves. A create-only save serializes mint + write or refuses any existing row and re-mints. Reserved slugs (`Default`, `Auto`) map to `wf_auto-workflow`.
- A canvas-free chat loses the only text teaching `config.params` (`edit_canvas`'s `set_node` description): a missing required param is a TODO (`V22`), so a refusal on `rep.todo` names the incomplete messages and Ask's graph guide says `config.params`.

## Prompt budget pins
- `renderScriptsSection` has ~400 bytes headroom (4713 of `SCRIPTS_SECTION_MAX_BYTES` 5120; `Buffer.byteLength`, em dash = 3 bytes); its `'byte-stable'` line re-renders with its own args. The Ask catalog must stay `< 8000` (7929 measured). Composer rule 11's opening words are regex-pinned in `ask-prompt.test.mjs` (`… block\. A project: line/`): widen it in the same task. `NOTE_TAIL` pins: [[claude-cli-binary-scan]].
- `COMPOSER_ALLOW` includes `test_script`/`list_scripts`/`get_script`: editing their texts changes composer defs — gate on `composerMode`, identity-check with `scripts:{enabled:true}` (`tools.mjs` imports alone via `git show`). `composer-deps.mjs` behaviour identity: run the checkpoint copy as a `.tmp.mjs` beside it on the same calls, normalizing ids (`/\b([nw])_[a-z0-9]{8}\b/g`).
- `ASK_CODEX_REWRITES` needs each `from` EXACTLY once in `ASK_SYSTEM_RULES`; `ask-prompt-codex` forbids `never from a sub-agent` in Codex rules: give new sub-agent text a rewrite pair (to `''`).

## Graph drawing on chat cards
- build_workflow cards: `buildGraph` → `{op:'layout'}` → `autoLayout(…, {describe:true})`; `card.workflow` and `card.manifest.graph` share x/y, kept verbatim by the composer. Auto/propose_workflow: `assemble.mjs` → `autoLayout` WITHOUT `describe`, so stacks are spaced for no footer: drawing footer (+46) and band (+24) overlaps ~32 px. `nodeSize` bills `DESC_H` whenever `describe` is set. Re-running `autoLayout` taller keeps x but moves a loop-only card's y.
- Manifests carry no description text (`manifestAgents`): footer text comes from `/api/agents?all=1` + `/api/scripts` (`loadLibrary`: TTL 15 s, `lib.tried`; pins allow <= 2 GETs per TTL when failing, none while hidden).
- `renderAutoProposal` is shared with the run page's Auto question (`renderWorkflowBody` → `.wf-preview`, `openWorkflowPopup`; pins `ui-auto-proposal`, `ui-auto-build`, `ui-question-workflow`, `ui-running-auto`): chat-only changes are opt-in. The Workflows chat dock never renders Auto cards (`COMPOSER_ALLOW` lacks `propose_workflow`).
- `playAssembly` reads `view.flowLayout()?.order` (null on a non-flow view: lands at once) — pass an order. `view.setAgents()` rewrites wire classes, dropping `is-hid`. `.ask-ccard` max 760 px; `.ask-card` is `min(var(--chat-card-max),100cqi)`. The card graph's ResizeObserver targets `.ask-wfcard-graph`, disconnected on dispose.
- An Auto card's `card.nodes[id]` is a DISPLAY row: Save posts `diffNodes(card.nodes, wf.nodes)` and `applyTunables`; merging `card.nodes` through `TUNABLE_KEYS` freezes `fanOut`/`askQuestions` on every node (a mutant survives the suite) — apply only `wf.nodes`.
- A new pannable host (`view.createNav`) needs `user-select:none` (Chrome drag-pans select text; jsdom cannot show it): prove with CDP press-move-release on a page served over http, then `String(getSelection())`.
