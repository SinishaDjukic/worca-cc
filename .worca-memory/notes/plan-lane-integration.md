Replay mechanics: [[plan-replay-verification]], [[plan-dry-run-recipe]].

## Cycle shape
- Wave 1: one foreground opus lane per phase replays it in its own checkpoint clone (later phases stacked read-only on a sibling lane's tree) + one requirements lane, all in one message. From cycle 2 on, clone the previous cycle's composed tree and RUN it: CI CDP proofs, a live headless-Chrome walk beside the mockup ([[ui-cdp-audit-traps]]), backend probes via real modules, jsdom probes on the plan's boot() harness, a parity inventory, one fence check ("composed + 9337 tests, 0 fail" had never run a CDP proof: 2 of 7 failed).
- Wave 2: FRESH foreground lanes (wave-1 report pasted, its scratch reused) each OWN a plan line range and write an edits file; the applier refuses an OLD that is not unique, outside `--range`, or overlapping another file's. Split a phase by FUNCTION line ranges when two lanes need it.
- Merge all edits files in one pass, add refiner-only header/handoff edits, write the port, THEN run one integration lane on the merged text (it finds prose-only renames no phase lane can).

## Integrating lane trees
- Slice the merged plan and each lane's `plan-patched.md` by `## Phase X` and compare; gaps = OTHER lanes' edits and refiner-only edits — rerun the owning lane's relift script on the merged plan, never hand-merge.
- `git fetch <lane tree> <branch>:laneX`, then per phase `git diff <lane commit before the phase> <phase end> -- . ':!<files an earlier phase created>' | git apply -3 --index` (3-way absorbs lanes on different earlier-phase versions unless both touch one region). Fix lanes branched from the composed tree: `git diff <base> fix | git apply -3 --index`.
- Prove: each file a fence creates whole equals the plan's concatenation (`fences.join('\n\n') + '\n'`); each non-command fence body is in some tracked file (else a Replace OLD, a `KEEP`/`PASTE` placeholder or an import merged into a block); `node --check`; full suite on the final commit AND each phase commit (second clone); rerun flakes alone and on a checkpoint clone. The import exemption hides a fence that LACKS an import (`ReferenceError` survived 5 cycles): run each appended test fence verbatim at its task base.

## Traps
- **The fence proof is blind to prose DELETE lists** (34 rules a "delete by selector" list named survived three cycles). Generate the confirm grep FROM the list and prove it 3 ways: > 0 at checkpoint, > 0 on the skipping tree, 0 after applying the list. Grep the WHOLE plan for each selector before fencing a deletion: fence it in the earliest task, later tasks grep-confirm.
- Phase-end trees built by PARTITIONING fix commits by task skip prose ops, and "create it now with Task D2's code" freezes an old version: grep for "'s code"/"until then create", copy each later fence into the earlier phase tree. A lane's "base" can fold in a LATER task's one-liner: diff each lane base against the plan's **Files:** lines.
- Two phases appending at EOF (style.css, a shared test file) conflict under `-3`: ours-then-theirs, or rebuild from the fences. Concatenating two appended `test(…)` blocks in a `cherry-pick` conflict DROPS a `});` (the shared closing line sits after `>>>>>>>`): `node --check`, then order tests as the plan does.
- Prose-only renames have no lane: a rename into a SINGLE-quoted JS string with an apostrophe breaks parsing (the plan must say `view\'s`).
- **Read-only audit lanes' code-bearing ops have no replaying lane** (five contract-lane ops reached a merged plan untested). The integration lane lists every op whose NEW changes a backticked code span, implements each in the combined tree, then mutates every NEW rule SENTENCE, not just the rows the notes list.

## Edits file from a fixed tree
- Fix the CODE in a scratch tree first (base = the plan's earlier tasks; one branch with fences as-is, one fixed): RED on as-is with the new tests, GREEN + mutants on fixed. New fence bodies come from the fixed tree byte-exact (Create = file minus final `\n`); a test file fed by several "(append)" fences splits at each section's first line (seams `\n\n`) and must rebuild exactly.
- Hunks (line-LCS of fence vs new body, or `git diff -U0 <base> fix`): grow context (k|k, k|k+1, k+1|k) until OLD occurs ONCE in the WHOLE plan, merging touching blocks; never start or end on a blank line (`indexOf('', i)` never advances); OLD and NEW ≥ 1 line each. The found line picks the edits file by owned range; a hunk at a fence SEAM matches the next task (anchor by hand); unfound hunks = prose-built code → a new "Replace (exact, once) … with …" op or a prose patch. Prose edits: plan line + FROM/TO markers, NEW may say `{{OLD}}`; never end a marker on a space.
- Verify: relift every changed fence from the PATCHED plan (pair old/new fences by first line; swap whole bodies on the BASE file; an html fence with `<!-- PASTE -->` lines swaps changed lines only); `git diff fix relift` empty; run tests there. Prose-patched app.js tasks: an anchored-insert script per step, with the patched AND the original plan so the RED shows.
- **Prose-only task → Replace/With fences:** diff from the PHASE's base in the composed tree, never the checkpoint (an earlier prose task may have touched the file); relift at that base AND at checkpoint + earlier edit; fold hunks ≤ 3 lines apart; whole-file fence when > ~1/4 changes. Base for a hand-applied phase commit with lanes on top: HEAD with its hunks reversed (`git diff <c>^ <c> -- <files> | git apply -R --index`).
- Big PROSE plan whose checkpoint moved: anchored node patches (`@@FIND…@@REPLACE…@@END` once; `@@SECTION <line> @@UNTIL <heading>`); check `SCHEMA_VERSION`/`applySchemaV<n>` vs the plan's number, `ls test/` per created file, grep each cited OLD line number.

## Shipping a dry run as the plan
- One commit per task in the scratch clone; per task a tests patch + a source patch as labelled `~~~~diff T<n>-test` / `T<n>-src` fences at column 0, assembled by node (never Write); a ```diff fence breaks on a docs patch holding ``` lines, so refuse a patch holding a `~~~~` line. The refiner writes ONLY the plan port and the verdict (no patch files in the pipeline dir). Give the plan a node one-liner extractor (`indexOf("~~~~diff " + label)` → next `~~~~`) and prove it by running that exact line from the FINAL port over a fresh checkpoint clone, all fences in order, then `git diff --cached --quiet <composed>`; plus per-wave apply-order convergence, each task green ALONE on its wave base, tests-only RED, full suite.
- Fan-out: one scratch clone per AREA, a red-first pin + fix per finding; integrate as `fixup! T<n>` (shared file → the LAST task), autosquash; run the squash clone after EACH fixup pair. A killer written on the FINISHED tree can import later tasks' modules: split it by the latest module it needs. A tip fixup editing an import line a LATER task also extends (or one merely ADJACENT to its new import lines) conflicts at autosquash: keep fixups off such import blocks (duck-type `e?.code === 'TOO_LARGE'`) or add a separate `import { x } from './archive.mjs';` line below the next unchanged import (duplicate-source imports have precedent).
- Assembler: an ALREADY-APPLIED guard compares whole LINES (`src.includes(body)` skips a substring insert); assert `{`/`}` balance vs a "down to the closing brace" range; never `trimEnd()` a patch (a blank context line is one `' '`); Files lists from `git diff --name-status`; an UNCLOSED fence passes `git apply` — refuse a fence holding a Step line, `cmp` each fence with its commit's diff.
