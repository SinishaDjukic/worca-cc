Straight answers

Before you ask

The run pauses instead of failing, and the reason is written to the audit trail. Step index, loop state, models and every step's Claude session id are saved. After your window resets you resume from History, the CLI, or /resume in chat — the interrupted step re-attaches its session rather than starting over.
No — it drives it. Worca spawns the claude CLI headlessly, one process per step, and adds the state machine, gates, audit trail, budgets, model routing and history around it.
Yes. Model and effort resolve per node and apply to that step's spawn only. Custom models carry their own base URL and token; values written as ${VAR} are read from your shell at spawn instead of being stored.
One SQLite database at ~/.worca-cc/worca-cc.db and a markdown store beside it — both outside your repo. Agents edit inside a dedicated git worktree on their own branch.
Node 22.13+, the claude CLI on your PATH, and npm install. Two runtime dependencies, no build step. The web UI binds to 127.0.0.1 only.
