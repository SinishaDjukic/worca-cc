# Requirements (A7: the Product brief) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One optional Product brief per project or workspace, made in one deeper read-only look at the repository's default branch, edited by the product owner, read by every interview round of that scope; with a brief a new feature skips its own look and offers **Look closer** on demand; the brief records the commit and branch it came from and says when the code moved on.

**Architecture:** Pure brief logic (prompt, paths, normalisation, merge, rendering, staleness intersection) in `src/core/requirements/brief.mjs`; the job (default branch, checkout, call, costs, recovery, staleness git calls) in `brief-job.mjs`, reusing A1's `callModel` and repo look; one row per scope in a new `req_briefs` table; spend in `req_cost_ledger` with a new `brief_id`. The interview gains one prompt block and the orientation skip in small, separate hunks of `round.mjs` / `interview.mjs`. The page module `ui/public/requirements-view.mjs` gains the brief page and the two feature-side changes. Lane 1 (A1.1) is merged in by Task 10.

**Tech Stack:** Node ESM, `node:sqlite`, `node:test`, jsdom, Express (`ui/server.mjs`), vanilla DOM (`ui/public/*.mjs`).

**Spec:** `plans/requirements-a7-design.md` (decisions D1–D17 win where this plan is unclear). A1: `plans/requirements-design.md` (A1-D<n>); A2: `plans/requirements-a2-design.md` (A2-D<n>); A1.1: `plans/requirements-a11-design.md` on `feat/req-a11-interview-model` (A1.1-D<n>).

**Visual reference (UI tasks):** the approved mock's source files, one per board (their folder is given with each UI task's dispatch; they are not part of the repository): `BriefEmpty.dc.html` (board 11, no brief yet, notes card, list header), `Brief.dc.html` (board 12, made, code moved on), `NewFeatureBrief.dc.html` (board 13), `LookCloser.dc.html` (board 14, What Worca knows, both states, and the workspace note). They use upstream's classes (`card`, `badge`, `chip`, `btn`, `btn-mini`, `btn-go`, `hint`, `code`, `field`, `select-wrap`, `subtitle`) and tokens; inline styles are layout hints. Where the design doc deviates from a board (D7: one Refresh button; Q-C) the doc wins; what no board shows is listed in design §6 "Not on the boards": build exactly that, nothing more.

## Global Constraints

- One commit per task (Task 10 is a merge commit plus one follow-up commit); every message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Subjects start `Requirements:`.
- **Lane rules.** Before Task 10, edits to `src/core/requirements/round.mjs` and `interview.mjs` are only the hunks named in Tasks 4 and 5 (lane 1 rewrites the system prompts, the prompt order, the call options and the model choice). No local machine paths in shipped files.
- No model call in the brief job before the refusals of design §5 (switch off, no repository or default branch, busy, `MAX_BRIEF_JOBS`, budget) have passed; a refusal writes nothing.
- The brief look reads the ref from `defaultBranchRef` (the checked-out branch only as its last fallback), uses `REPO_LOOK_TOOLS` only, `BRIEF_MAX_TURNS = 40`, `BRIEF_TIMEOUT_MS = 600_000` over checkout and call together, an aux spawn through `callModel` (only through the `briefCall` helper); every checkout is closed in `finally`.
- Every stored path is relative to the checkout (workspace: `repos/<key>/…`), with `/` separators, in the brief and in areas added from a closer look.
- The product owner's edited sections are never overwritten by a look (D6); areas with `added` survive a refresh; **Add this to the brief** never replaces an existing area.
- Without a usable brief, `buildRoundPrompt` returns exactly A2's text.
- Every `/api/requirements*` route is in `REQUIREMENTS_ROUTES` behind `requireFlag('requirements')`; brief frames go through `requirementsBriefNotifier` (silent while the flag is off).
- Mock mode (`WORCA_MOCK=1`) never spawns a model and never writes outside `<worcaHome>/tmp/requirements`.
- No import from Shaper code. Core modules never import `ui/server.mjs`; `git-info.mjs` stays a leaf (brief-job imports it, never the reverse). `style.css`: tokens only.
- Errors from routes: `{ error }` with 400 / 404 / 409 / 500 (A1 §5).
- One test file: `node tools/test.mjs test/<file>.test.mjs`. Full suite: `npm test` (compare failures with the base branch before blaming this one).

## Review Focus

1. **A feature created while its project has a brief.** Expect no `looking` status or frame, an `orientation` turn `{ skipped: 'brief' }`, no `runClaudeImpl` call for a look, no budget check for it, round 1's prompt containing `<product_brief>`, and the round payload's `brief` (Task 5).
2. **Refresh with edits.** Edit "Who uses it", add an area from a closer look on "Orders", refresh: expect the edited section unchanged, the model's "Orders" area still there next to the added "Orders: <feature>" area, the other sections replaced, `sources` / `files` / `made_at` new (Tasks 2, 4, 5).
3. **Staleness.** Make a brief on a test repository whose checkout is on a feature branch: expect the default branch's sha. Commit to the default branch a change to a file an area lists and one to an unrelated file: expect `commits: 2`, `touching: 1`, that area named; reset the branch to before the brief's commit and commit again: expect `known: false, reason: 'rewritten'`; delete the branch: `branch-gone` (Tasks 3, 4, 6).
4. **Spend.** A brief look at the spending limit is refused 409 `BUDGET` with nothing written; a good one books one ledger row with `brief_id` and `feature_seq = 0`; Statistics' feature count does not grow (Tasks 1, 4).
5. **Flag off.** Every new route 404; no frame (Task 6).
6. **After the lane 1 merge.** A1.1's pinned round prompt test green; the brief call is `callModel(d, { kind: 'look', …, systemPrompt: BRIEF_SYSTEM_PROMPT, maxTurns: BRIEF_MAX_TURNS })` in replace mode with the hermetic flags and `interviewModel`'s model and effort; no `'brief'` kind exists (Task 10).
